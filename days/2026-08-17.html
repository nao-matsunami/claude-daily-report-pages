3. Claude Code — クロスセッションメッセージング

v2.1.224 以降、macOS / Linux で稼働。/peers は実在

[確認済] 公式ドキュメントで Gemini の主張はすべて裏が取れた: v2.1.224 以降、macOS/Linux(WSL2 含む)のみ、native Windows 非対応、Bedrock / Claude Platform on AWS / Google Cloud Agent Platform / Microsoft Foundry では利用不可、同一マシン内は per-session ソケット経由で Anthropic サーバを経由しない、送るのはプレーンテキストのみ。/list-agents の別名として /peers も原文に明記されており、Gemini の固有名捏造ではない。

→ https://code.claude.com/docs/en/cross-session-messaging

今日の注目(検証・実装を試す価値があるもの)

1. v2.1.233 の Todo/タスクツール既定オフ — 自リポジトリの棚卸しを推奨(最優先)

2. v2.1.232 の Bash 権限変更が 2.1.233 で一部リバートされた件
Cygwin 形式シンボリックリンク(Windows)と入力リダイレクト < file の権限チェックが取り消された。8/15 時点のブリーフ・knowledge に「< file も権限チェック対象になった」と書いていれば、その前提は今は成立していない(将来もっと限定的な形で戻る、と原文にある)。権限設計の記述を持つ knowledge の訂正対象。3AIとも見落としており、changelog を1日単位で追う価値の実例になっている。

3. CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS(v2.1.233)
この検証パイプライン自体が毎日同じ一次ソース(changelog / release notes / newsroom)を WebFetch している。既定 15 分の URL キャッシュ TTL を延ばせば、1回のブリーフ内で複数エージェントが同じページを引くときのトークンとレイテンシを削れる可能性がある。効果測定が単純で、失敗しても影響が局所的なので実験しやすい。
