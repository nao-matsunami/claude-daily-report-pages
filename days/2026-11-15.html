  • 理由:公式ガイドが数値付きで、「never ○○」型の古い注意書きや、常設の「委譲せよ」指示を見直すよう勧めています。memory や knowledge、エージェント定義が多いこのパイプラインは、まさに対象です。
  • 注意:ハーネスが過去のターンを編集すると、prefix check で 400 エラーになります。独自 API 呼び出しがある場合は、履歴の扱いを先に確認してください。
  • 検討:Claude Code での effort の既定値は medium です。無人実行で high を指定するかどうかも決めておくとよいです。
  1. Code Mode(A-6)の対話での試用と hooks の挙動確認
  • 理由:hooks の扱いが通常と違います。Code Mode では、PreToolUse hook が失敗やタイムアウトしたとき、onFailure を設定していなくても呼び出しを拒否します(fail-closed)。既存知見 hooks-timeout-fail-open-primary-check.md の前提とは別の扱いなので、試す価値があります。
  • 制約:-p では使えないので、自動化には入りません。対話セッションで手元の hooks がタイムアウトしないか確認するところまでです。
