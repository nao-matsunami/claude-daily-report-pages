審判レポート：Claude/Anthropic の直近の動き（2026-10-02〜10-09）

前提: 収集元は codex と Claude の2系統だけです。両者が一致していても独立した確認は2件にとどまるため、主要な事項は WebFetch で一次情報（anthropic.com / code.claude.com / platform.claude.com / support.claude.com / claude.com）を直接確認しました。「一次確認できず」は確認できなかったという意味で、誤りと判定したわけではありません。

A. Claude Code

A-1. v2.1.295：hooks に onFailure: "block"

[確認済] command / HTTP フックが起動できない、タイムアウトする、異常終了する場合に、通すのではなく操作をブロックできるようになりました（fail-closed）。両AIが一致し、changelog 原文でも確認しました。既知のとおり hooks は既定で fail-open なので、それを選択的に閉じる手段です。
出典: https://code.claude.com/docs/en/changelog

A-2. v2.1.295：サブエージェントが事前読み込みする skills は最大32件・各1回

[確認済] 両AIが一致し、原文でも確認しました。残りの skill は Skill ツール経由で呼び出せます。同じ版で、tool search 経由の MCP ツール説明の上限が 2,048 → 16,384 文字になったことも原文で確認しました（Claude のみが報告）。
出典: changelog

A-3. v2.1.294：命令形で書いた prompt / agent hook の誤判定を修正

[確認済] 「Block commands that…」のように命令形で書いたフックが、本来ブロックすべき操作を許可していた不具合の修正です。Stop / SubagentStop の命令形プロンプトの判定も改善されました。両AIが一致し、原文でも確認しました。
出典: changelog

A-4. v2.1.293：Bash で読んだファイルの CLAUDE.md / パス指定 rules が読み込まれない問題を修正

[確認済] 原文に記載がある対象コマンドは cat / head / tail / sed -n / grep です。同じ版で、compaction 後に完了済み作業を撤回・再実行する問題と、HTTP MCP のメモリリークも修正されています。
出典: changelog

A-5. v2.1.293：Haiku 5.5 が Anthropic API での既定の Haiku モデルに

[確認済] 原文に「1M context, $0.10/$0.50 per Mtok（100K 超は $0.50/$2.50）」とあります。報告したのは Claude だけですが、原文と一致しました。
出典: changelog

A-6. v2.1.292：Agent ツールに effort パラメータ

[確認済] 原文では 2.1.292（10/6）の Added です。codex の「v2.1.291〜292」という書き方は不正確で、2.1.291 の中身は回帰修正2件（終了時に末尾メッセージが失われる問題など）だけです。同じ 2.1.292 には、claude plugin install --marketplace、allowed-tools が後のターンに復活する問題の修正、compaction 要約の /name からユーザー専用 skill を誤起動する問題の修正、hook 出力に含まれる <system-reminder> のエスケープも入っています（いずれも原文で確認）。

※ この knowledge の本文は今回読めていません。knowledge 側に記録された導入版が 2.1.292 より前になっている場合は、版の帰属が食い違っていることになるので、照合をお勧めします。

A-7. v2.1.290：再開したサブエージェント / teammate が thinking とプロンプトキャッシュを失う問題を修正

[確認済] 両AIが一致し、原文でも確認しました。compaction 後に /loop などの予約タスクが復元されない問題も修正されています（原文では「この版以降の compaction が対象」と限定付き）。シンボリックリンクで作業ディレクトリ外を指す CLAUDE.md / rule / AGENTS.md が読み取り制限を無視して読み込まれる問題の修正も確認しました。

  • Claude の「大きなセッションの resume が高速化」は、原文の文言と違います。原文は「transcript の読み込み中もタイマー・入力・描画が止まらなくなった」という応答性の改善で、速くなったとは書かれていません。

A-8. v2.1.289：環境変数を前置した Bash と、シンボリックリンク経由の Read で deny / ask が効かない問題を修正

[確認済] 原文は対象を codex の要約より狭く書いています。

  • Bash 側は、sandbox がコマンドを自動許可している場合に限った修正です。
  • Read 側は、@メンションした、または IDE で選択・変更したファイルがシンボリックリンク経由だった場合の修正です。
  • codex が挙げた「大きいファイルのプラグイン画面表示の改善」は、取得できた範囲には見当たりませんでした。原文に無いと確認したわけではありません。

A-9. v2.1.288：hooks のマッチング失敗時に「スキップ」から「ブロック」へ変更、CLAUDE.md 関連の修正

[確認済]（報告は Claude のみ、原文と一致）

  • PreToolUse / PermissionRequest フックで、マッチングに失敗した場合や入力を JSON にできない場合に、スキップではなくブロックするよう変わりました。
  • CLAUDE.md が二重に付与される問題が修正されました。
  • Write / Edit で触れたファイルでも、パス指定 rules とネストした CLAUDE.md が読み込まれるようになりました。
  • プラグイン定義のエージェントが、自前の prompt / tools / effort で動くよう修正されました。

今日の注目

  1. onFailure: "block"（v2.1.295）と、v2.1.288 の「マッチング失敗時はブロック」

既知の fail-open 問題（hooks-timeout-fail-open-primary-check）に対する公式の対処です。deny 床を hooks で担っている箇所に onFailure: "block" を付けるか棚卸しする価値があります。v2.1.294 の命令形 prompt hook 修正と合わせて、自分の prompt hook が意図どおりブロックするかも実機で確かめるべきです。

  1. Haiku 5.5 の移行の注意点と、サブエージェントでの使い方

budget_tokens は 400 エラーになり、thinking ブロックも既定で返ります。100k トークン超は単価が5倍になるので、探索・トリアージ用のサブエージェントに割り当てるなら、Agent ツールの effort（2.1.292）と組み合わせて、費用と品質をセットで測るのが妥当です。リポジトリ内で budget_tokens を指定している箇所の洗い出しも必要です。

  1. WebSearch 予算が「200回で終了」から「1時間あたり100回で補充」に変わった（v2.1.290）
