1. モデル

Claude Fable 5.2 / Mythos 5.2 の発表(11/9)

[確認済](両AIが一致し、一次ソースとも合っています)

  • API ID は claude-fable-5-2、料金は $8/$40 です。fast mode は $16/$80 で、最大2.5倍速くなります。1M コンテキスト、最大出力 128k です(128k は platform の release notes に記載があり、発表ページには書かれていません)。
  • Mythos 5.2 を使えるのは、検証プログラムに認定された組織だけです。effort は5段階で、アプリと Claude Code の既定は Medium です。出力は最大30%速く、安全機能によるブロックは約55%減ったとされています。
  • ベンチマークの数値(FrontierCode 2.0 49.1%、FrontierSWE v2 69.9%、Terminal-Bench-Science 74.6%、OSWorld 2.1 89.3%、AutomationBench 51.4%(Gemini 4 Carbon の 53.9% を下回る))は、Claude の出力が公式の表と一致しました。ただし Anthropic 自身が出した数字で、第三者による追試はありません。
  • 旧版の Fable 5.1 が $10/$50 だったという記述は、既存の知見と合っています。
  • 出典:https://www.anthropic.com/claude-fable-and-mythos-5-2 ・ https://platform.claude.com/docs/en/release-notes/overview

補足:Fable 5.2 への移行で API が 400 を返すケース(収集外、検証中に判明)

[確認済](platform release notes 11/9)

  • 5.2 は、すべてのアカウントで prefix check を強制します。system・tools・以前のメッセージを書き換えたうえで 5.2 の thinking ブロックを送り返すと、400 エラーになります。
  • computer use は computer_toolset_20260801 だけが使えます。旧 computer_20251124 は、Bedrock 以外では 400 になります。
  • advisor tool では、実行側を 5.2 にすると、advisor も 5.2 か Mythos 5.2 でないと 400 になります。
  • 出典:同上

2. Claude Code(すべて changelog 原文で照合)

v2.1.321(11/9):Fable 5.2 対応と既定モデルの移行

[確認済]

  • claude-fable-5-2 が Fable の既定になりました。キャッシュの読み出しは $0.20/Mtok です。5.1 に戻すには /model claude-fable-5-1 を使います。
  • Claude の出力は「二次情報による」としていましたが、changelog 原文に書かれています。

v2.1.321:hooks の修正

[確認済](両AIが一致)

  • PreToolUse の ask が、別の hook の defer が先に終わると失われる問題を修正しました。
  • 大きな hook 出力が、同じツール呼び出しにある別の hook の出力ファイルを指してしまう問題を修正しました。
  • mcp_tool hook の応答が 16 MiB を超えると hook が飛ばされていた問題を修正し、そのツール呼び出しは拒否されるようになりました。

v2.1.321:skills / commands / agents が消える問題の修正と、読み込み範囲の変更

[確認済]

  • worktree に入った後や、git stash などでフォルダが消えて戻った後に、skills などが消えたままになる問題を修正しました。
  • ~/.claude/plugins の中にある .claude/skills は読み込まれなくなりました。

v2.1.321:1,000文字を超える出力の省略、/context 見積もりの修正、圧縮をまたぐ auto mode の報告消失の修正

[確認済](Claude だけが主張、原文と一致)

v2.1.321:MCP OAuth のリダイレクトで秘密情報が別ホストに送られる問題の修正

[確認済](Claude だけが主張、原文と一致)

  • セキュリティ修正です。MCP OAuth を使っているなら、早めに更新してください。

v2.1.319(11/6):MCP tasks

[確認済](両AIが一致)

  • MCP サーバーがツール呼び出しを task として実行した場合だけ、すぐにバックグラウンドへ移ります。CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND を設定すると、バックグラウンドに移さず待つようになります。
  • Claude の出力にある「長時間かかる呼び出しは自動でバックグラウンドに回る」は、言い過ぎです。codex の「通常の MCP 呼び出しまで非同期になるわけではない」という書き方が正確です。

v2.1.319:permissions.denyInsteadOfPrompting

[確認済](両AIが一致)

  • 許可プロンプトで止まるはずの呼び出しを拒否し、そのままターンを続けます。ターミナルのセッション、サブエージェント、teammates で効きます。

v2.1.319:テレメトリ無効や gateway 環境での auto mode の変更

[確認済]

  • サーバーで判定できない呼び出しは、確認を求めるか拒否するかのどちらかになり、組み込み分類器へのフォールバックはなくなりました。元に戻すには CLAUDE_CODE_AUTO_MODE_SERVER=0 を設定します。

-

v2.1.319:自分で間隔を決める /loop の終了条件変更

[確認済]

  • 次を予約しないまま終わったら終了するようになりました。以前の動作に戻すには CLAUDE_CODE_LOOP_KEEPALIVE=1 です。

-

v2.1.319:その他

[確認済]

  • /claude-api latency-optimize が追加されました。対象は API アプリのコードで、Claude Code 自体を速くするものではないという codex の説明が正確です。
  • /context の表は各リストの上位10行に絞られ、表示用グリッドを毎ターン送っていた問題も修正されました。
  • /clear が稼働中のバックグラウンド処理を止めてしまう問題を修正しました。
  • /tasks に「Earlier in this session」が加わりました。
  • PostToolUse hook は、割り込みの後に終わった呼び出しでも最大10秒実行されます。
  • Bash sandbox が有効なとき、下の階層の .claude/skills は、そこで起動するか /cd したときだけ読み込まれます。

v2.1.318(11/4)

[確認済]

  • バックグラウンドのサブエージェントは、シェルコマンドを3分でバックグラウンドへ移すようになりました(全プロバイダー共通)。
  • mod の $.model.fork に effort が追加されました。
  • 次の問題を修正しました:macOS で多数の Bash 実行中にメモリが増えて止まる、idle compaction が要約でない応答で会話を置き換える、--continue で過去の会話を失う(2.1.314 からの退行)、-p や SDK で失敗したカスタムコマンドが何も表示しない。
  • サブエージェントの effort が v2.1.317 の変更だという点は、既存の知見と合っています。

v2.1.317(11/3)

[確認済](Claude だけが主張、原文と一致)

  • Read ツールの「前回から変更なし」という省略表示を廃止しました。
  • 大きな CLAUDE.md が変わった後、自動圧縮をすると "Prompt is too long" になる問題を修正しました。
  • Agent SDK の hook callback に onFailure: "block" が加わりました。
  • 補足:v2.1.320 の項目は、取得した範囲の changelog には見当たりませんでした。どちらのAIも言及していません。欠番かどうかは断定できません。

3. Cowork / デスクトップ / Enterprise

Cowork v4.16336.0(11/3):desktopHome の既定値変更と旧設定の非推奨化

Cowork v4.23118.1(11/9):plugin(mod)のコードによるツール呼び出しには承認カードを出さない

[確認済](Claude だけが主張、原文と一致)

  • 原文では、toolPolicy に登録されていない connector のツールも、承認カードなしで実行されます。ask に設定したツールへの呼び出しは拒否されます。Claude の出力は、この補足を書いていませんでした。
  • 同じ版で、sandbox が有効なときはサブフォルダの skills を読み込まなくなりました。
  • 出典:https://claude.com/docs/cowork/changelog

今日の注目

  1. permissions.denyInsteadOfPrompting(v2.1.319)を cron の claude -p で試す
  • 無人実行で許可待ちのまま止まる問題を、設定1つで避けられる可能性があります。

  • あわせて、Enterprise では 11/30 に Skills が Plugins に名前を変えます。Team/Enterprise で Skills を無効にしている組織は、11/30 から plugins が止まる点にも注意が必要です。
