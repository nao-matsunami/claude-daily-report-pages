Claude / Anthropic 直近の動き 審判まとめ(2026-10-12〜10-18)

検証方法: 入力は codex と Claude の2系統だけです。片方だけの主張でも、一次情報(code.claude.com changelog、platform.claude.com リリースノート、claude.com Cowork changelog、support.claude.com、anthropic.com/news)で本文を確認できたものは [確認済] にしました。

A. Claude Code(最重視)

A-1. アイドル時コンパクション(v2.1.299 / 10/14)

[確認済] 20万トークン以上の会話を約54分放置すると、1時間キャッシュが切れる前に圧縮されます。閾値は CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS、無効化は "idleCompaction": false です。changelog 原文には「どちらも v2.1.290 以降が必要」とも書かれています。v2.1.302 で /config に「Idle compaction」の行が追加されたことも確認しました。両AIが一致しています。
出典: https://code.claude.com/docs/en/changelog

A-2. CLAUDE_CODE_DISABLE_FILE_MENTIONS(v2.1.299)

[確認済] @ で指定したファイルは、中身ではなくパスだけが渡され、Claude がファイルツールで読みます。両AIが一致しています。
出典: 同上

A-3. hooks の実行順と失敗時の扱い(v2.1.299 / v2.1.300)

[確認済] v2.1.299 では次の3点が変わりました。

  • UserPromptSubmit が skill / カスタムコマンドの展開前に実行されるようになり、ブロックすると埋め込みシェルも止まります。
  • skill の frontmatter に書いた UserPromptSubmit は、その skill を呼んだ入力の次の入力から実行されます。
  • プラグイン hook に値を渡せない、または返答を受け取れないときは、操作が通らずに拒否されます(fail-closed)。

v2.1.300 では、PreToolUse / PermissionRequest hook の updatedInput が厳密に検証されるようになりました。未知のキーは捨てられ、ツールが受け付けない入力なら呼び出しは拒否されます。codex は frontmatter の件だけ、Claude は全項目を挙げていましたが、すべて原文で確認しました。

A-4. MCP 許可ルールの厳格化(v2.1.299、破壊的変更)

[確認済] mcp__a は a__b や a_ という名前のサーバーを許可しなくなりました。正規化後のサーバー名をすべて書いた mcp__<server>__* 形式が必要です。主張は Claude だけですが、原文で確認しました。

A-5. v2.1.299 のその他

[確認済] 以下はいずれも原文で確認しました。主張は Claude だけで、/reload-skills は両AIが挙げています。

  • /usage に警告を追加(max effort / workflows / 常時ロードされるコンテキスト / 大きなツール結果)
  • 名前に不可視文字・文字方向を変える文字・< > を含む skill やコマンドは読み込まない
  • WebFetch の effort が呼び出し元の設定を引き継ぐ
  • agent view で /effort と /fast を使い、新しいセッションの初期値を決められる
  • /reload-skills の説明を明確化(圧縮後に skill を再認識させる手段)

A-6. Mods の拡張(v2.1.300)

[確認済] agent.spawn hook で workflow agent の prompt と model を書き換えられるようになりました(以前は拒否しかできませんでした)。あわせて prompt.change hook と virtualText が追加されました。主張は codex だけですが、原文で確認しました。

A-7. ToolSearch・/tasks・キャッシュミスの修正(v2.1.300 / v2.1.302)

[確認済] v2.1.300 で次の2件が修正されました。

  • 自動 ToolSearch(ENABLE_TOOL_SEARCH=auto)が会話の途中で切れる問題
  • メッセージを送ったサブエージェントが、完了後に /tasks から消える問題

v2.1.302 では、途中で追加したツールを ToolSearch や圧縮後に再ロードしたときのキャッシュミスが修正されました。主張は codex です。

A-8. OpenTelemetry の拡充(v2.1.300 / v2.1.301)

[確認済]

  • v2.1.300: api_request イベントでキャッシュ書き込みを cache_creation_5m_tokens と cache_creation_1h_tokens に分けて出力。トレースの span に gen_ai.* 属性を追加
  • v2.1.301: tool_decision イベントに classifier_verdict と permission_mode を追加

両AIが一致しています。

A-9. 無人実行の待機上限と worktree 修正(v2.1.301)

[確認済] CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS が追加されました。リセットまで遠い利用上限に当たると、待たずにそのリクエストを終了します。また、WorktreeCreate hook が作った worktree を、未push のコミットがあり得るのに終了時に無確認で削除していた問題が修正されました。両AIが一致しています。

A-10. fork サブエージェントの既定ONを拡大 / サードパーティプロバイダーでの権限モード初期値(v2.1.302)

[確認済] fork サブエージェントが claude -p、Agent SDK、デスクトップ、VS Code でも既定で有効になりました。無効化は CLAUDE_CODE_FORK_SUBAGENT=0 です。

同じ版で、サードパーティプロバイダー上の claude -p と Agent SDK のセッションは、権限モードを指定しないと default で始まるようになりました。条件はテレメトリが off、または新規インストールの場合です。--permission-mode auto を付ければ auto のままです。両AIが一致しています(権限モードの件は codex だけ)。

A-11. v2.1.300〜302 のその他

[確認済] 以下はいずれも原文で確認しました。主張は Claude だけです。

  • hook の同時実行は同じイベントで最大12個まで、残りは順番待ち(v2.1.302)
  • CLAUDE_CODE_AUTO_MODE_MODEL で、クライアント側の auto mode 分類器のモデルを選べる。サーバー側の auto mode には効かない
  • デスクトップと VS Code では、メイン会話のサブエージェントを常にバックグラウンドで実行
  • Claude in Chrome の指示の位置を変え、共有プロンプトキャッシュに乗るようにした
  • Claude Platform on AWS で /advisor を追加(v2.1.300)
  • ローカルのトランスクリプトに、各リクエストのシステムプロンプト・ツール・パラメータも記録
  • 終了時、止めるよう指示してから1.5秒経っても動いているバックグラウンドコマンドを強制終了
  • 小さいコンテキストのモデルに切り替えると、切り替え前のモデルが先に要約する(v2.1.301)
  • vim モードに % モーションを追加
  • claude-api skill に OTel トレース設定ガイドを追加

C. Claude Design

C-1. スタンドアロン版 Claude Design が 12/14 に閉鎖

[確認済] 閉鎖日は 2026-12-14 です。移行ガイドには次のことが書かれています。

  • デザインシステムは1回の移行で組織分がまとめて移る
  • チャットとコメントは引き継がれず、閉鎖後に削除される
  • 公開リンクは閉鎖後に使えなくなる
  • ZDR の組織は artifacts を有効にできないため移行できず、「Project archive」で個別にダウンロードする

Claude Code v2.1.302 で /design-sync と /design-login に閉鎖の告知が追加されたことも確認しました。移行ガイドの公開日は「1週間以上前に更新」としか書かれておらず、初出日は一次確認できませんでした。両AIが一致しています。
出典: https://support.claude.com/en/articles/17440474-migrate-from-standalone-claude-design-to-claude

C-2. Enterprise で Design が既定有効に(10/15)

出典: https://support.claude.com/en/articles/14604416-get-started-with-claude-design
