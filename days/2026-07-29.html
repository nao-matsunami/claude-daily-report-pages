1. モデル / API

Claude Opus 5 リリース（2026年7月24日）

[確認済] 3AI一致。公式ニュース・リリースノートで確認。1Mコンテキスト（デフォルト＝上限）、最大出力128k、$5/$25 per MTok（Opus 4.8と同額）、Claude API / Amazon Bedrock / Google Cloud / Microsoft Foundry で提供。リリースノートの表現は「Claude Fable 5 のフロンティア知能に迫る性能を半額で」で、Geminiの「Fable 5に迫る性能でコスト半減」は正確。
https://www.anthropic.com/news/claude-opus-5

Opus 5 の破壊的変更：thinking デフォルトON / thinking無効化は effort high 以下に限定

[確認済] ChatGPT・Claude が一致、同梱APIリファレンスでも確認。thinking を省略すると adaptive で動作（4.8/4.7は無思考だった）。thinking:{"type":"disabled"} は effort xhigh/max と併用すると400エラー。effort は low〜max の5段階。
https://platform.claude.com/docs/en/release-notes/api

プロンプトキャッシュ最小長 1024 → 512 トークン（Opus 5）

[確認済] Geminiのみが挙げた「未確認」項目だが、APIリファレンスで裏が取れた。Geminiの主張が正しい。

会話途中でのツール変更（ベータ）

[確認済] Gemini・ChatGPT・Claude すべてが言及、リファレンスで確認。ヘッダ mid-conversation-tool-changes-2026-07-01。messages に role:"system" の tool_addition / tool_removal ブロックを挿入する方式で、対象ツールは事前に defer_loading: true で宣言しておく必要がある。プロンプトキャッシュを壊さずにツールセットを変更できる。

server-side fallback に "default" モード追加

[確認済] ChatGPT・Claudeが一致、リファレンスで確認。ヘッダ server-side-fallback-2026-07-01。拒否カテゴリに応じて推奨フォールバックモデルへ自動ルーティング（cyber カテゴリ → Opus 4.8）。従来の配列形式は -2026-06-01 ヘッダのままで、ヘッダと形式を取り違えると400。

Opus 4.7 の fast mode 廃止

[確認済] ChatGPT・Claude一致。Claude Code changelog とAPIリファレンス双方で確認。fast mode は Opus 5 / Opus 4.8 のみ（Claude API限定、Bedrock等は非対応）。Opus 5 の fast mode は $10/$50 per MTok。
※補足：当環境の内部説明文には「fast mode は Opus 5/4.8/4.7 で利用可」との記述が残っており、changelog と食い違います。changelog（日付明記あり）が新しいので、そちらを信頼すべきですが、実機で /fast を試す際は要確認。

今日の注目（検証・実装を試す価値のある更新）

1. Claude Code：サブエージェントのネスト深さ 3 への拡大（v2.1.219）
デフォルト値が 1 → 3 に変わったのは、既存のエージェント構成の挙動が黙って変わる種類の変更です。マルチエージェント構成を組んでいるなら、意図しない再帰的なファンアウトでトークン消費が跳ねていないか今すぐ確認する価値があります。無効化は CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1。手元が v2.1.220 なので即検証できます。

2. Opus 5 の thinking / effort 周りの破壊的変更
thinking:{"type":"disabled"} を xhigh/max と組み合わせている既存コードは 400 で落ちます。しかもこの検証はリクエスト単位なので、途中で effort を上げる実装は「最初は通るのに後で落ちる」形になります。加えて「thinking を省略＝無思考」だった 4.8 の前提が崩れ、max_tokens が thinking と出力の合計に効くため、切り詰めた max_tokens は途中切断のリスクがあります。キャッシュ最小長が 512 に下がった件も、「短すぎてキャッシュ不可」と諦めていたプロンプトを見直す好機です。

3. /code-review のバックグラウンドサブエージェント化（v2.1.218）
レビューが会話コンテキストを占有しなくなったため、実装作業と並行してレビューを回すワークフローが現実的になりました。既存の運用手順（レビュー完了を待ってから次に進む等）を組み替える価値があります。
