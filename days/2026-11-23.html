Claude/Anthropic 直近の動き 審判まとめ(2026-11-16〜11-23)

前提として、収集元は codex と Claude の2系統だけです。主要な項目は一次情報で照合しました(changelog、support/platform の各リリースノート、Cowork changelog、anthropic.com/news、Code Mode・skills・sub-agents の docs)。

A. Claude Code

A-1. v2.1.328〜329:Code Mode で hooks の挙動が変わった
[確認済] 両AIが一致し、changelog と Code Mode docs の原文で確認しました。2.1.328 から、Code Mode のスクリプト出力には UserPromptSubmit(managed を含む)が走りません。出力を伏せるには PostToolUse の updatedToolOutput を使います。2.1.329 からは、PreToolUse hook がエラーになってもツール呼び出しが拒否されなくなりました(fail-open)。必ず止めたい command / HTTP / MCP tool hook には "onFailure": "block" の明示が必要です。

  • 版数の誤り:Claude は UserPromptSubmit の件を 2.1.329 としていますが、正しくは 2.1.328 です。
  • 出典:https://code.claude.com/docs/en/changelog / https://code.claude.com/docs/en/code-mode

A-2. v2.1.328:CLAUDE_CODE_FORK_SUBAGENT=0 のときは子サブエージェントを待つのが既定に
[確認済] codex だけが挙げた項目ですが、changelog 原文で確認しました。対象は claude -p、Agent SDK、Desktop、VS Code のサブエージェントで、自分の子サブエージェントの完了を既定で待つようになります。fork 既定ON に関する既存知見の続きにあたる変更です。

A-3. v2.1.327:/status に設定不備の一覧が出る
[確認済] 両AIが一致し、原文で確認しました。表示されるのは、壊れた agent / skill / command / output style ファイル、keybinding のエラー、使えない sandbox、無視されている permission 設定、一度も一致しない hook matcher です。同じ版で claude mcp add-json <name> - も追加され、JSON を標準入力から読めます。ただし Claude Code のセッション内では使えません。

A-4. v2.1.328:auto mode で「任意のパッケージを実行する」allow ルールの無視が広がった
[確認済。ただし Claude の記述には誤りあり] 原文の例は Bash(pnpm dlx ) と /usr/bin/npm run: で、npx は名指しされていません。Claude はこの件を 2.1.327 としていますが、正しくは 2.1.328 です。2.1.326 にも、プログラム名のないワイルドカードや $HOME で始まる allow ルールを無視する変更があります。

A-5. v2.1.329:auto mode の git status 実行を減らし、/tasks の表示対象を拡張
[確認済] 両AIが一致し、原文で確認しました。/tasks では予約タスク、/loop の起動予定、goal、会話の fork が表示され、x で停止できます。原文には「変更を捨てる git コマンドは、作業ツリーを確認するまでブロックされることがある」という但し書きもあります。

A-6. v2.1.330:定期タスクと /loop の上限が7日から30日に。easel、VS Code の /fork・/workflows も追加

A-7. v2.1.330 のその他の変更
[確認済] Claude だけが挙げた項目ですが、すべて原文で確認しました。

  • Enterprise Admin Console で管理される組織にサインインできるようになった。
  • model を指定した skill でも、context: fork 以外ならサブエージェント・fork・compaction・/recap はセッションのモデルのまま動く。
  • Prompt hooks の model に haiku や sonnet などのエイリアスを書ける。
  • ルート・ホーム・トップレベル・作業フォルダを狙う rm で承認を求める範囲が広がった。応答できる人がいない場合は拒否される。
  • 長い会話を compact した直後に数分固まる不具合が修正された。

A-8. v2.1.328:Bedrock などのサードパーティ環境で auto mode が使えるように。/code-review は /simplify と分担
[確認済] Claude だけが挙げた項目ですが、原文で確認しました。auto mode の対象は Opus 4.6 / Sonnet 4.6 で、環境は Bedrock、Google Cloud Agent Platform、Microsoft Foundry、Claude apps gateway です。mcp_tool hooks でも onFailure: block が使えるようになりました。

  • ラベルの訂正:Claude は「自動 compaction がシステムプロンプトを組み直すようになった」を【二次】としていましたが、実際は公式 changelog 2.1.328 に Fix として載っている一次情報です。

A-10. Code Mode の有効化は CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1
[確認済] Claude は【二次・未確認】としていましたが、公式 docs で確認できました。プロジェクト設定に書いた場合は無視されます。managed settings で 0 にすると組織全体で無効にできます。利用は対話ターミナルだけで、gateway / Bedrock では使えません。公式 docs にトークン削減量の数値は載っていません。

B-3. Cowork changelog の 11/17〜11/20 分(v6.6395.0、v6.28899.2、v6.28899.6)
[確認済] Claude だけが挙げた項目ですが、すべて原文で確認しました。

  • v6.28899.6:SSH ホストに Claude Code 2.1.330 が必要。定期タスクの上限が30日になり、scheduledTasksEnabled: false で全部止められる。
  • v6.28899.2:(破壊的変更)SSH セッションでは手元のプロジェクト単位・ローカル単位の plugin 設定が無視される。managed settings の PostToolUse は、ツール開始前に拒否された呼び出しでは動かなくなった。この hook でログを取っている場合は、その分の記録が抜ける。

  • 旧設定キーの期限:coworkTabEnabled などは 12/17 12:00 PT から読まれなくなる。
  • Claude の記述の補足:MCP の allow / deny リストについて、Claude は「切り替えに変更」と書いていますが、正確には 11/19 版で 6.6395.0 より前の挙動に差し戻しています。Chat / Cowork でも適用したい場合は、desktopMcpServersListScope: all を設定してオプトインします。
