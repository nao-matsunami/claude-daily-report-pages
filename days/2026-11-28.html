A. Claude Code

A-1. v2.1.332（11/25）：MCP サーバーがスキルを提供可能に（ベータ）＋ PreSkillShellCommand hook

[確認済]（両AIが一致、changelog 原文あり）
MCP サーバーが持ち込むスキルは / メニューに server:skill という名前で出ます。新しい hook イベント PreSkillShellCommand は、スキルやコマンドを読み込むときに、中に書かれたシェルコマンドを拒否できます。原文には「2.1.331 以前の版では、この hook を書いた設定ファイルがあると起動時にダイアログが出る」という注意もあります。
出典：https://code.claude.com/docs/en/changelog

A-3. v2.1.332：その他の挙動変更

[確認済]（Claude だけが挙げたが、原文あり）

  • macOS で computer use が有効な場合、computer-use は予約済みのスキル名になり、同名の自作スキルやコマンドは読み込まれなくなります。
  • --model default を指定していてそのモデルが使えない場合、エラーで止まらず旧モデルに切り替わります。auto mode 中は、auto mode が受け付けるモデルにだけ切り替わります。
  • Desktop の Code タブの OTel service.name が claude-code-desktop に変わりました。元の名前を使い続けるには OTEL_SERVICE_NAME を設定します。
  • Desktop の Code タブで Anthropic API を使い、ゲートウェイのアドレスと一緒に設定した場合、200K 未満の CLAUDE_CODE_AUTO_COMPACT_WINDOW は無視されます。代わりに /autocompact を使います。

A-4. v2.1.332：メモリとコンテキスト消費の改善

[確認済]（codex だけが挙げたが、原文あり）
次の改善が原文にあります。

  • 長い会話の再開時、ツールの多い MCP 環境での起動時、claude -p や SDK セッションの開始時のメモリ使用
  • computer use を実際に使うまでのコンテキスト消費
  • Code Mode の再開時に「以前のスクリプト変数は失われた」と Claude に最初から伝える

改善率の数値は原文にもありません。これは codex の記述どおりです。

A-9. v2.1.330（11/20）：/loop と定期タスクが最長30日に、ほか

[確認済]（Claude だけが挙げたが、原文あり）

  • 30日になるのはセッションが動き続けている間だけです。この版より前に作ったタスクは7日で終わります。
  • ルート・ホーム・トップレベル・作業フォルダを狙う rm は、承認を求めるケースが増えました。答える人がいない場面では拒否されます。
  • その他：スキルの model 設定がサブエージェント・fork・compaction・/recap に及ばなくなったこと、組み込み mod「easel」の追加、VS Code への /fork 追加、/design-sync が Storybook のフォールバックビルドにプロジェクト内の Storybook だけを使うこと。いずれも原文で確認しました。

A-10. Code Mode の運用上の注意（有効化の方法、REPL、審査がコード単位、onFailure: "block"、PostToolUse、UserPromptSubmit）

[確認済]（Claude が挙げた。docs 原文とすべて一致）

  • 有効化は CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 で、プロジェクトの設定ファイルに書いても無視されます。
  • auto mode の審査はツール呼び出しごとではなく、コード1本ごとです。実行中に決まる値は審査で見えません。
  • hook には cd 'app' && git push のような複合コマンドが届きます。
  • hook が失敗したときに確実に止めるには "onFailure": "block" を設定します。
  • コード出力の検査は REPL に一致させた PostToolUse hook で行います。v2.1.328 以降、UserPromptSubmit hook にはコード出力が届きません。

出典：https://code.claude.com/docs/en/code-mode

A-11. Claude Ship（11/23）と /ship

[確認済]（codex だけが挙げたが、公式記事あり）
Code Review（GA）に、ベータのエージェント2つが加わります。

  • PR Steward：失敗した CI、マージの競合、レビュー指摘に対応します。承認やマージはしません。
  • Claude Approvals：リポジトリに置いたポリシーファイルに基づいて承認を判断します。

対象は Team / Enterprise の GitHub リポジトリで、ZDR、HIPAA 構成、顧客管理の暗号鍵を使う組織は対象外です。公式は、Approvals をまず observe モードで試すよう勧めています。ただし observe モード中でも、Claude のレビューを起動するポリシーには Code Review の課金が発生します。/ship は Claude Code と Desktop で 11/23 から段階的に展開中です。2.1.330〜332 の changelog には /ship の記載が見当たりませんでした。これは「記載を確認できなかった」という意味で、「存在しない」という意味ではありません。
出典：https://claude.com/resources/articles/introducing-claude-ship

B. Cowork / Desktop

B-1. v7.37095.0（11/24）

[確認済]（Claude だけが挙げたが、Cowork changelog の原文あり）

  • ローカル MCP ツール呼び出しが60秒でタイムアウトする不具合を修正しました。Cowork と Chat では既定で最長3分まで実行できます。

  • macOS では plugin の hook が、以前は止めなかった操作を止める場合があります。公式は「まず1台の Mac で試す」よう勧めています。
  • サードパーティ配備向けに Design と Slides（ベータ、既定はオフ）が追加されました。使うには artifactsEnabled と、artifactsDesignEnabled か artifactsSlidesEnabled の少なくとも一方を設定します。

今日の注目

  1. PreSkillShellCommand と MCP 由来のスキル（v2.1.332）

外部の MCP サーバーが、インラインのシェルコマンドを含むスキルを持ち込めるようになりました。無人実行の防御線に新しい経路が加わったことになります。この hook で拒否できるかどうかを実機で確かめる価値があります。2.1.331 以前の版では、この hook を書いた設定があると起動時にダイアログが出るため、cron で古い版が混ざっていると止まるリスクもあります。

  1. サードパーティの Sonnet 5 / 5.5 で auto mode が既定に、--model default は旧モデルに切り替わる（v2.1.332）
  1. Cowork v7.37095.0：macOS の plugin hook の挙動変更とハードリンクの拒否

後片付け：使ったのは WebFetch だけで、ローカルのタブ・アプリ・プロセスは起動していないため、後片付けの対象はありません。
