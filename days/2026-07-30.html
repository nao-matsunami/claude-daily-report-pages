2. Opus 5 の API 破壊的変更（重要）

[確認済]
codexが挙げた項目はいずれも公式ドキュメント（platform.claude.com／同梱の Anthropic 公式リファレンス）と一致しました。

  • thinking がデフォルト有効（Opus 4.8/4.7 は省略時オフ → 逆転）
  • thinking: {"type":"disabled"} は effort high 以下のみ許可、xhigh/max で 400
  • prompt cache の最小キャッシュ長が 1,024 → 512 tokens
  • 1M context（デフォルト＝最大）／128K max output
  • Fast mode は $10/$50、Claude API 限定の research preview（Bedrock / Google Cloud / Foundry 非対応）
  • mid-conversation tool changes（beta ヘッダ mid-conversation-tool-changes-2026-07-01）
  • fallbacks: "default"（beta ヘッダ server-side-fallback-2026-07-01）でカテゴリ別自動フォールバック（cyber → Opus 4.8）

https://platform.claude.com/docs/en/about-claude/models/whats-new-opus-5

要注意: max_tokens は thinking + 応答本文の合計上限です。thinking を設定していなかった既存ルートは応答が途中で切れる破壊的変更を受けます。codex/Claude いずれも明示していなかった実害ポイントです。

6. MCP 2026-07-28 仕様（期間内・重要）

[確認済] 2026年7月28日、MCP 第5次スペック公開。Gemini・Claude が一致し、一次ソースでも裏付け。

  • ステートレスコアへ移行（双方向ステートフル → リクエスト/レスポンス。各リクエストが自前でプロトコルバージョン・クライアント識別・capabilities を持つため、共有ストレージなしのロードバランサ配下・サーバーレス/エッジで動く）

  • 拡張の正式化: Tasks（experimental core から昇格）／MCP Apps／Enterprise Managed Auth
  • MRTR（Multi Round-Trip Requests）がサーバー起点リクエストを置換、Mcp-Method/Mcp-Name ヘッダによるルーティング
  • Claude側: 埋め込みUI、enterprise-managed auth、開発者向けオブザーバビリティ・ダッシュボード、MCP Tunnels（research preview／プライベートネットワーク内のMCPサーバーに公開露出なしで接続）。コネクタディレクトリは950+サーバー。

https://blog.modelcontextprotocol.io/posts/2026-07-28/ ／ https://claude.com/blog/bringing-mcp-2026-07-28-to-claude

今日の注目（検証・実装を試す価値がある更新）

1位: Opus 5 の thinking デフォルト有効 × max_tokens

既存コードで thinking を明示していないルートは、今日から思考トークンを消費し、max_tokens が thinking＋本文の合算上限になるため、応答が途中で切れる実害が出ます。さらに thinking: {"type":"disabled"} × effort xhigh/max は 400。自分のコード/エージェントで max_tokens と effort の組み合わせを棚卸しし、1リクエストずつ実測するのが最優先。cache 最小長 1024→512 も、これまで「短くてキャッシュ不可」と諦めていたプロンプトがコード変更なしで効くようになるため、cache_read_input_tokens を測り直す価値があります。

2位: Claude Code の sandbox.network.strictAllowlist と DirectoryAdded フック

どちらも自分の環境で今すぐ試せて、効果が観測可能な追加です。strictAllowlist はサンドボックス実行時に許可リスト外ホストをプロンプトなしで拒否するため、自動化・CI でのエージェント実行の安全側デフォルトとして即投入できます。DirectoryAdded は /add-dir や SDK の register_repo_root に反応するので、マルチリポ作業時の自動セットアップ（依存インストール、CLAUDE.md 読み込み、lint 設定）をフック化できます。

3位: MCP Tunnels（research preview）と Enterprise Managed Auth

社内ネットワークのMCPサーバーを公開露出・ファイアウォール変更・IP許可リストなしでClaudeに繋げられるのは、これまで「社内APIはMCP化しても届かない」で止まっていた案件を動かす変更です。合わせて、ステートレスコア移行により自作MCPサーバーをサーバーレス/エッジに置けるようになったので、既存サーバーの再デプロイ形態を見直す好機。ただしresearch previewのため、本番投入前に可用性の前提を確認してください。

確認できなかった項目（憶測で補完していません）: Claude Design のバックエンドモデル更新の有無／ボイスモードの正確な対応言語数／ジェイルブレイク深刻度フレームワークの一次情報／agent-memory-2026-07-22 beta の一次情報／v2.1.219 の一部バグ修正細目（subagent depth 3、claude-api スキル既定変更、claude -p 修正）の逐語確認。
