A. Claude Code（v2.1.325〜329）

A-1. Code Mode を agent teams と同時に使えるように（2.1.326）
[確認済] 両AI＋一次。agent teams を有効にしたセッションでも Code Mode をオンにできるようになりました。すでにオンにしていた人は、teams 付きのセッションが Code Mode で始まります。
https://code.claude.com/docs/en/changelog

A-2. Code Mode の PreToolUse hook がエラーになっても止めなくなった（2.1.329）／"onFailure": "block" の拡張（2.1.328）
[確認済] 両AI＋一次。Code Mode 外と同じく、エラーになった PreToolUse hook はスクリプトのツール呼び出しを拒否しなくなりました。必ず止めたい hook には "onFailure": "block" を明示します。2.1.328 からは mcp_tool hook も対応しています。

A-3. "decision": "block" が効く場面が増えた（2.1.326）
[確認済] Claude のみの主張ですが、一次原文と一致しました。常に block を出力している hook は、実際に呼び出しを止め始める可能性があると明記されています。

A-4. /status で壊れた設定を一覧表示（2.1.327）
[確認済] 両AI＋一次。壊れた agent／skill／command／output style ファイル、キーバインドのエラー、使えないサンドボックス、無視された権限設定、一度もマッチしない hook マッチャが表示されます。

A-5. Code Mode から 0.75 秒の待機を除去（2.1.328）
[確認済] 両AI＋一次。auto モードと bypass モードで、大半のスクリプトの後にあった待機がなくなりました。
codex の「MCP 利用時のキャッシュとツール説明の長さも改善」は [要検証] です。読めた範囲では一次確認できませんでした。

A-6. 長時間セッションのメモリ改善（2.1.328／2.1.329）
[確認済] 両AI＋一次。対象は、多数のファイルを編集する長いセッション、大きな MCP 結果を含む長い Desktop セッション（macOS／Linux）、画像の多いセッションの再開です。

A-7. autoCompactWindow の修正（2.1.329）
[確認済] codex＋一次。codex の要約は大まかすぎます。正確には「事前に起動しておいたプロセスから始めたセッションが、プロジェクトの .claude/settings.json の autoCompactWindow を無視していた」問題の修正です。

A-9. skills／commands／agents フォルダを検出し損ねる問題の修正（2.1.329）

A-10. ポリシーが読み込めないとき auto mode で始まる（2.1.326）

A-11. auto mode が「任意のパッケージを実行できる」allow ルールを無視（2.1.327）

A-13. モデル未指定のサブエージェントは、再開時も起動時のモデルを使い続ける（2.1.327）

A-14. /code-review の報告範囲を絞り、整理は /simplify に（2.1.328）／対象なしの実行でブランチ全体をレビュー（2.1.329）

A-15. Code Mode の出力を UserPromptSubmit hook に渡さなくなった（2.1.328）
[確認済] Claude のみの主張ですが、一次原文と一致しました。managed の hook も対象です。出力を伏せ字にしたい場合は、PostToolUse hook の updatedToolOutput を使います。

A-16. CLAUDE_CODE_FORK_SUBAGENT=0 時の待機と、claude -p の10分上限（2.1.328）
[確認済] Claude のみの主張ですが、一次原文と一致しました。-p では、バックグラウンドのサブエージェントとその子をまとめて10分で打ち切ります。延ばすには CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS を設定します。

A-17. 2.1.329 のその他の変更
[確認済] Claude のみの主張ですが、一次原文と一致しました。

  • /tasks にスケジュールタスク、/loop の起床、goal、fork を表示
  • 旧バージョンで保存したスケジュールタスクの多くは、新しいサインインセッションで再登録が必要。ただし自分のセッションを --resume すれば実行される

今日の注目

  1. hooks の失敗時の挙動変更（2.1.326 と 2.1.329）への棚卸し

2つの変更が逆向きに効きます。

  • Code Mode では、エラーになった PreToolUse hook が止めなくなった（緩む方向）
  • "decision": "block" が効く場面が増えた（厳しくなる方向）
  1. cron の claude -p への影響（2.1.328 と 2.1.329）
  • CLAUDE_CODE_FORK_SUBAGENT=0 のとき、バックグラウンドのサブエージェントは子と合わせて10分で打ち切られる
  • 旧バージョンで保存したスケジュールタスクは再登録が必要になる

検証パイプラインのように、サブエージェントの連鎖が長い無人実行は黙って途中で切られる恐れがあります。CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS の要否を確認する価値があります。

  1. Cowork 11/19 の保持期間の変更（3P）と、11/13 のサンドボックス確認の変更
  • 保持期間は、更新前に 3650 日にしておかないとデータが完全に削除される可能性がある
  • サンドボックス内のシェルが確認を求めるようになり、routine が確認画面で止まる可能性がある
