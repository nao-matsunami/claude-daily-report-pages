A. Claude Code（CLI）

A-1. v2.1.302：fork サブエージェントが -p/SDK/desktop/VS Code でも既定ON

  • [確認済]（両AI一致、changelog 原文あり）
  • CLAUDE_CODE_FORK_SUBAGENT=0 でオフにできます。claude mcp serve は fork を提供しません。同じ版で次の3点も追加されています。
  • CLAUDE_CODE_AUTO_MODE_MODEL（クライアント側の分類器だけが対象）
  • /config の Idle compaction 行
  • prompt/agent hook の同時実行数を、1イベントあたり12に制限

-

  • https://code.claude.com/docs/en/changelog

A-2. v2.1.299〜300：Idle compaction、UserPromptSubmit の実行順変更、MCP allow の厳密化、OTel キャッシュ内訳

  • [確認済]（Claude 単独の主張だが、changelog 原文で裏が取れた）
  • Idle compaction は、200K トークン以上の会話が約54分アイドルになると実行されます。無効化は "idleCompaction": false、閾値の変更は CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS です。
  • UserPromptSubmit hook は、スキルやコマンドの展開「前」に動くようになりました。
  • MCP の allow ルールは mcp__<server>__* の完全一致になりました。
  • OTel に cache_creation_5m/1h_tokens が追加されました。

今日の注目

  1. v2.1.307 の claude_code.safety_event（OTel）
  • 権限ルール、auto mode、hook、sandbox が止めたり確認を求めたりしたツール呼び出しが、1件ずつ記録されます。
  • 無人の claude -p cron で「何がブロックされて黙って失敗したか」を見られるようになります。fork の既定ON（A-1）や MCP allow の厳密化（A-2）の影響を、実測で確かめる手段として使えます。
  1. Cowork 10/22：要人手確認の MCP ツールを、予約タスクが黙って飛ばす
  • 予約タスクはエラーで止まらず、その呼び出しを省いて続行します。そのため、結果が欠けたまま「成功」に見える可能性があります。
  • 予約タスクで使っている MCP ツールに、要確認マークが付いていないかの棚卸しをお勧めします。Windows を使っているなら、B-3 の PreToolUse ブロックも併せて確認してください。
  1. Design →「Hand off to Claude Code」（10/20）と、12/14 の単独版終了
  • プロジェクトはまだ移行できず、チャットとコメントは終了後に削除されます。
  • 単独版に残っている資産がある場合は、hand-off でコード化するか、Project archive でエクスポートするかを、期限前に試して手順を決めておくべきです。
