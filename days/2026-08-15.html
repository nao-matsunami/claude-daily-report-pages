1. Claude Code 本体（CLI）

auto mode が新規セッションの既定の権限モードに（8/14 発効）

[確認済] Pro / Max / Team の新規セッションで auto mode が既定に。自分で設定した既定値は「一度きりの切替プロンプトを受け入れない限り維持」され、組織管理の既定値は不変。auto mode の classifier 呼び出しはこれらのプランで使用量にカウントされない（ただし Enterprise / Claude API / Bedrock / Vertex / Foundry ではトークン課金対象と docs に明記）。

  • https://code.claude.com/docs/en/whats-new/2026-w32

今日の注目

1. fork サブエージェント既定ON（v2.1.232）の実挙動確認 — 最優先

既定値の変更なので何もしなくても今日から挙動が変わるタイプの更新です。会話全体とプロンプトキャッシュを継承するため、「サブエージェントには文脈を再説明する」という従来の前提が崩れ、逆に親の文脈を渡したくない探索タスクで意図せず汚染が起きる可能性があります。加えて非teammateエージェントが既定でバックグラウンド実行になり、インライン表示されなくなる（/tasks で追う）点も運用に効きます。既存の subagent 定義・ワークフローがある repo なら、fork 継承の有無とトークン消費を実測する価値があります。

2. sandbox.ripgrep のプロジェクト設定禁止 — 静かに壊れる変更

v2.1.232 の破壊的変更で、プロジェクト設定に書いた sandbox.ripgrep は警告なく無効化されます。該当設定を使っている repo があるなら、user / managed / --settings への移設が必要です。grep で sandbox.ripgrep を洗い出すだけの低コストな確認で済み、放置すると原因の分かりにくいサンドボックス挙動差になります。

3. Compliance API の Claude Code カバー範囲（8/11）— 除外リストが実務の分かれ目

Enterprise 運用をしているなら、Claude Code on the web / Claude Platform 経由 / Bedrock・Vertex・Foundry 上のセッションが除外である点が重要です。「Claude Code は監査対象になった」と丸めると監査の穴を見落とします。どの実行経路を業務で使っているかと突き合わせる価値があります。
