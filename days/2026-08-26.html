今日の注目

1. フックの if 条件の誤発火修正（v2.1.243）— 挙動が変わる側の変更
Bash(cat *) のような if 条件が、$ やバッククォートの後に引数が続く無関係な Bash コマンドで発火していた不具合の修正です。これまで「たまたま発火していた」フックが発火しなくなる可能性があり、逆に絞り込み前提の構成では意図どおりに戻ります。新機能の追加と違い、既存の自動化の振る舞いが黙って変わる種類の変更なので、hooks を permissions 代わりに使っている構成の棚卸しが最優先だと考えます。

2. promptCacheTtl / subagentPromptCacheTtl（v2.1.243）— 実測可能なコスト削減
メイン会話1時間・サブエージェント5分という TTL 分離は、API キー／クラウドプロバイダ利用時のコストに直結します。同時に入った /usage の Loops ブレークダウンと /tasks のモデル＋effort 表示を合わせると、設定変更 → 効果測定 が同一リリース内で完結して検証できます。定量的に当たりはずれが出る数少ない項目です。

3. WebFetch の期限切れコンテンツ保持修正 ＋ Bedrock 二重課金修正（v2.1.239）
どちらも「気づかないまま損をしていた」型の修正です。WebFetch 側は長時間セッションのメモリとコンテキスト衛生に、Bedrock 側はプロキシ環境で API 課金が実際に倍になっていたという金銭影響に関わります。Bedrock 経由の構成があるなら請求実績の遡り確認、WebFetch を多用する定期実行があるならメモリ挙動の再測定に価値があります。
