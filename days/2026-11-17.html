A. Claude Code（重点）

A-1. v2.1.323: 実験的な Code Mode（オプトイン）
[確認済] 両AIが一致し、changelog と docs で一次確認しました。

  • CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 で有効になります。プロジェクト設定に書いた値は無視されます。
  • 使えるのは対話ターミナルだけです。-p、SDK、VS Code、Desktop、gateway、Bedrock などでは使えません。
  • 待機中のコードは10分、バックグラウンドは2時間で止まります。auto mode の分類器はツール呼び出しごとではなく、コード単位で審査します。
  • 生成コードを監査する場合は、PreToolUse で REPL にマッチさせ、tool_input.code を読みます。
  • 公式 docs はトークン削減効果に触れていません。

-

出典: https://code.claude.com/docs/en/code-mode

A-2. v2.1.323: claude -p／SDK で長時間動く hook に30秒ごとのハートビート
[確認済] 両AIが一致し、changelog 原文でも確認しました。ホスト側がハングと誤判定して終了する問題への対策です。

A-3. v2.1.323: plugin.json の engines["claude-code"]、claude plugin validate の TS 型検査
[確認済] 両AIが一致し、changelog で確認しました。

  • 対応バージョン範囲外のプラグインは、インストール・更新・読み込みのいずれも行われません。
  • 型検査の指摘は警告扱いで、--strict を付けると失敗になります。

[確認済] Claude だけの主張ですが、changelog で一次確認しました。200K に戻すには CLAUDE_CODE_DISABLE_1M_CONTEXT=1 を設定します。

A-5. v2.1.323: その他（/compact 修正、hook への agent_id、進捗サマリー無効化、subagentStatusLine 廃止）
[確認済] Claude だけの主張ですが、changelog で一次確認しました。

  • /compact を連続実行したときや /context の後に実行したとき、未回答のメッセージが要約で消える不具合が修正されました。
  • サブエージェントが compact するとき、PreCompact／PostCompact／SessionStart に agent_id／agent_type が渡るようになりました。
  • CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES が追加されました。原文では「2.1.318 から利用可能」となっています。
  • subagentStatusLine は廃止されました。既存の設定ファイルはそのまま読み込めます。

A-6. v2.1.325: サンドボックス内 Bash が既定で通常の権限確認を通るように
[確認済] Claude の主張です。Claude Code changelog と Cowork changelog（v5.11492.5）の両方で一次確認しました。

  • 以前の動作に戻すには sandbox.autoAllowBashIfSandboxed: true を設定します。
  • Cowork 側の記載では、管理設定の場合は managed-settings.json の sandbox ブロックに書き、新規ファイルではトップレベルに "parentSettingsBehavior": "merge" も必要です。
  • 既存 knowledge にこの項目そのものの棚卸しはありません。

A-7. v2.1.325: /loop・スケジュールタスクで、allowed-tools や hooks を宣言した skill の実行前に確認が入る
[確認済] Claude だけの主張ですが、changelog で確認しました。無人で回すには permissions.allow に Skill(name) を追加します。

A-8. v2.1.325: サブエージェント・コンテキスト関連の修正
[確認済] 両AIが一致し、changelog で確認しました。

  • opusplan／haiku 設定のとき、個別にモデルを指定したサブエージェントが plan 用モデルに置き換わる不具合が修正されました。
  • 別モデルのサブエージェントで、ファイル読み取りや MCP 結果の量が親モデル基準で決まる不具合が修正されました。
  • 多くのゲートウェイと Foundry で、compact せずに毎ターン context length エラーで止まる不具合が修正されました。
  • CLAUDE_CODE_MAX_CONTEXT_TOKENS が、claude- で始まる未知のモデルIDにも適用されるようになりました。
  • 補足: 「出力トークン上限で途中終了したサブエージェントに短く再回答させる」は、Fixed ではなく Improvements 欄の項目です。

D. モデル・プラットフォーム

D-1. Claude Fable 5.2 / Mythos 5.2 を発表（11/9）
[確認済] Claude だけの主張ですが、発表記事と release notes で一次確認しました。

  • 料金は $8/$40、fast mode は $16/$80 です。
  • アプリと Claude Code での既定の effort は Medium です。
  • FrontierSWE v2 は 69.9%（Opus 5.5 は 62.3%）、FrontierCode 2.0 は Xhigh で 49.1% です。
  • 出力速度は 5.1 比で最大30%向上しています。
  • 公式も「大半の作業は Opus 5.5 から始めること」を推奨しています。
  • Pro と Team 標準シートでは、Fable の利用は週間利用枠の最大50%までです。
  • Advisor として使える点は release notes で確認しました。「Orchestrator」という役割は一次確認できませんでした。
  • release notes には移行時の 400 系の変更点も載っています。thinking ブロックの前に system・tools・過去メッセージを編集すると 400 になる、computer_20251124 も 400 になる、ZDR は原則使えない、などです。
