A. Claude Code(重視)

A-1. Code Mode(実験的・opt-in)/ v2.1.323(11/12)
[確認済]
Claude が JavaScript を書き、その中で複数のツールをまとめて呼ぶ方式です。

  • 有効化は CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 です。シェルかユーザー設定に置きます。プロジェクトの settings に書いても無視されます。
  • 使えるのは端末の対話セッションだけです。-p、Agent SDK、VS Code、Desktop、クラウドセッションでは動きません。gateway・Bedrock・Foundry 経由も対象外です。
  • 対応モデルは Opus/Sonnet/Haiku 5.5 と Fable 5.2 です。
  • HIPAA・ZDR の組織、OpenTelemetry や DISABLE_TELEMETRY を設定している環境では起動しません。
  • 再開するときも Code Mode をオンにしておく必要があります。
  • auto mode の分類器は、ツール呼び出しごとではなくコード単位で審査します。
  • REPL にマッチする PreToolUse hook を書けば tool_input.code を検査できます。
  • コマンドは cd 'app' && git push のような形で hook に届くことがあります。

両AIの記述は一致しています。

https://code.claude.com/docs/en/code-mode ・ https://code.claude.com/docs/en/changelog

A-8. v2.1.326 の hooks / skills / サブエージェント関連の変更
[確認済]
Claude だけが挙げた項目ですが、すべて原文で確認しました。

  • "decision": "block" が効くケースが増えました。常に block を出力している hook は、これまで通っていた呼び出しを止め始める可能性があります。
  • 複数の hook が答える場合でも、PreToolUse の updatedInput が保持されやすくなりました。
  • /update-config のコンテキスト消費が約93,000→約13,000トークンに減りました。/help <command> も追加されています。
  • worktree に隔離されたサブエージェントは、共有ブランチを書き換えうる git コマンドを拒否します。
  • サブエージェントが20個を超えるときの CPU 負荷が改善されました。
  • plan mode の自動 compact が、回答中のモデル(例:opusplan 時の Opus)を使うようになりました。コストが上がる場合があります。

A-13. hooks 出力の 10,000 文字上限と、CLAUDE.md / additionalContext の使い分け
[確認済]

  • 上限を超えた出力はファイルに保存され、会話にはパスと先頭最大2,000文字のプレビューだけが入ります。この上限を引き上げる設定はありません。
  • 変わらない規約は CLAUDE.md、ブランチや CI 結果などの動的な情報は additionalContext に置くのが推奨です。
  • 途中の hook が出した値は、再開時に再生されるので古くなります。SessionStart の hook は再開時にもう一度走ります。

以上は公式 hooks 仕様で確認しました。上限がいつ導入されたかは確認できていません。根拠となった Zenn の検証記事は未読です。

今日の注目

  1. v2.1.325 の sandbox Bash 確認化と skill 実行前の確認(A-3・A-4)

無人で回している cron や /loop が、承認待ちで止まる可能性が最も高い変更です。

  • 既存の unattended-skill-confirm-inventory の棚卸しに、sandbox.autoAllowBashIfSandboxed を使っているかの確認を追加する価値があります。
  • 実機の claude -p で止まらないかも確かめるとよいです。
  1. v2.1.326 で "decision": "block" が効くケースが増えた(A-8)

常に block を返す hook や、条件の甘い hook があると、これまで通っていた呼び出しが止まり始めます。repo の hooks のうち、block を返す経路を洗い出す価値があります。

  1. desktopHome の 12/17 延期(B-3)

Code Mode(A-1)も話題性は大きいです。ただし -p、gateway、テレメトリ無効の環境では動かないため、定期実行のパイプラインには直接効きません。試すなら対話セッションでの手動検証になります。
