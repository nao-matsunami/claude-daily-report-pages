A. Claude Code（公式 changelog）

A-1. v2.1.312（10/27）：prompt / agent hooks の同時実行に上限
[確認済] 1セッションあたり同時実行は最大24本（サブエージェント分を含む）です。これとは別枠で、イベントの timeout を過ぎて待っているものが最大12本まで認められます。1秒未満の timeout は1秒として扱われます。数値は Claude 側の記述どおりで、codex は数値を挙げていません。2.1.302 にあった「同じイベントは最大12本まで同時実行」とは別のルールです。
出典: https://code.claude.com/docs/en/changelog

A-2. v2.1.312：サブエージェントの autoCompactWindow が CLAUDE_CODE_AUTO_COMPACT_WINDOW を引き下げられるように
[確認済] これまでは効果がなかった設定が、環境変数の窓を小さくする方向にだけ効くようになりました。大きくはできません。両AIの記述は一致し、原文とも合っています。
出典: 同上

A-3. v2.1.312：巨大な CLAUDE.md / rules を先頭だけ読んで上書きする不具合の修正、cd 後に paths: skills が見つからない不具合の修正
[確認済] 修正後は、Write ツールが「全部読むか、その場で編集するか」を Claude に求めます。対象は、サブディレクトリ内の CLAUDE.md、rules ファイル、@-include されたファイルです。もう一方は、git リポジトリ内で Bash の cd で深く移動した後に、ディレクトリ別の skills や paths: skills が見つからない不具合です。両AIとも挙げています。
出典: 同上

A-4. v2.1.312：その他の変更
[確認済] 次の3点です。

  • 利用上限の表示名が「session limit」から「5-hour limit」に変わりました。
  • Bedrock / Vertex / Foundry / Mantle で Claude Code が認識できないモデル名を使うと、短いシステムプロンプトが使われます。元に戻すには CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 を設定します。
  • クラウドで動く routine の作成・編集画面で、effort を選べるようになりました（codex のみが記載）。

出典: 同上

A-5. v2.1.311（10/26）：ultrathink でそのターンが xhigh effort に
[確認済] 条件は「対話ターミナル」で、「Anthropic API 経由の Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1」を使っている場合です。Claude 側の「5.x系」という書き方は範囲が広すぎます。対象は上の4モデルに限られます。作業中に打ち込むと、そのターンの残りが引き上げられます。
出典: 同上、https://code.claude.com/docs/en/model-config

A-6. v2.1.311：DISABLE_COMPACT、/code-review の effort、起動・コンパクション・/usage・IDE の修正
[確認済]

  • DISABLE_COMPACT は、settings ファイルと mod の $.env.set ではコンパクションをオフにする方向にしか効かなくなりました。
  • /code-review の原文は「effort レベルを最初に置き、max は頼まれたときだけ使うよう Claude に指示」です。Claude 側の「既定の effort が変わった」はこれを解釈した言い方です。
  • Pro / Max では、前回の確認から1時間以内の起動時にネットワーク要求を2つ省きます。
  • 要約が返らなかったときは、置き換える前に1回だけ再要求します。
  • /usage に大きなキャッシュミスが表示されない不具合を修正しました。
  • VS Code / JetBrains から送るカスタム skill に、開いているファイルや選択範囲が付かない不具合を修正しました。

出典: 同上

今日の注目

  1. Cowork の desktopHome 破壊的変更（B-1）：期限が 11/10 12:00 PT と決まっており、元に戻すのが難しい種類の変更です。coworkTabEnabled: false で Cowork を隠している環境では、desktopHome を明示的に設定しないと Cowork が表示されます。管理している設定を今週中に確認する価値があります。
  2. hooks の同時実行上限と1秒未満 timeout の切り上げ（A-1）：このリポジトリには hooks に依存する自動化があります。今回の変更で、待たされる hook が出たり、timeout が実質延びたりする可能性があります。timeout が1秒未満の hook と、同時に多数起動する prompt / agent hooks の有無を棚卸しすると良さそうです。2.1.311 の SubagentStop 修正（A-7）を受けた既存の監査と同じ手順で確認できます。
  3. agent_summary のコスト測定（F-2）：主張は1人の測定だけですが、バックグラウンドのサブエージェントで長いコマンドを待つ使い方をしているなら、確かめる意味があります。OTel で agent_summary の query source を絞り込めば、低コストで再現を確認できます。コスト管理には、D-1 の新しい Analytics API も一緒に検討できます。
