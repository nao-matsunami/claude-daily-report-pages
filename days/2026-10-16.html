Claude/Anthropic 直近の動き 突き合わせ結果(2026-10-16)

検証方法:ChatGPT(codex)と Claude の2系統の出力を突き合わせました。主な主張は、以下の一次情報で直接確認しています。

  • Claude Code changelog(code.claude.com)

  • anthropic.com/news

ラベル:2系統が一致し一次情報でも確認できた項目は [確認済] です。片方だけの主張でも、一次情報で裏が取れたものは [確認済] にしています。

A. Claude Code(最重要)

A-1. アイドル時コンパクション(2.1.299 / 10-14) [確認済]

  • 200K トークン以上の会話を約54分放置すると、1時間のキャッシュが切れる前に圧縮します。
  • 閾値は CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS で変えられます。"idleCompaction": false で無効になります。
  • 両設定とも「v2.1.290 以降が必要」と注記があり、codex の留保は正確でした。
  • 両AIが一致しています。
  • 出典: https://code.claude.com/docs/en/changelog

A-2. CLAUDE_CODE_DISABLE_FILE_MENTIONS(2.1.299) [確認済]

  • @ で指定したファイルは、中身ではなくパスで渡されます。Claude がツールで読みに行きます。
  • 両AIが一致しています。出典: 同上

A-3. Hooks onFailure: "block"(2.1.295 / 10-08) [確認済]

  • command / HTTP hook が起動失敗・タイムアウト・想定外の終了をしたとき、処理を素通しせずブロックします。
  • 両AIが一致しています。既定が fail-open だという既存知見と整合し、それを補う設定です。

A-4. Hooks 関連の挙動変更(2.1.294 / 2.1.299 / 2.1.300) [確認済]

  • 2.1.294: 指示文で書いた prompt / agent hook がブロックすべき操作を通してしまう不具合を修正。
  • 2.1.299: UserPromptSubmit がスキル・スラッシュコマンドの展開前に実行されるようになりました。ブロックすると、埋め込まれたシェルコマンドも実行されません。
  • 2.1.300: PreToolUse / PermissionRequest hook の updatedInput は、Claude 自身の入力と同じ検証にかかります。未知のキーは捨てられ、ツールが受け付けない入力なら呼び出しが拒否されます。
  • Claude 側だけの主張でしたが、一次情報で確認しました。

A-5. MCP 許可ルールの厳密化(2.1.299) [確認済]

  • mcp__a と書いても、a__b や a_ という名前のサーバーには一致しなくなりました。
  • 書き方は mcp__<正規化後のサーバー名>__* です。エージェントの tools: も同じ扱いです。
  • 既存設定に影響する可能性があります。 Claude 側だけの主張でしたが、一次情報で確認しました。

A-6. サブエージェント・スキル・MCP の各種変更(2.1.295〜2.1.296) [確認済]

  • サブエージェントの autoCompactWindow(frontmatter / --agents)
  • Read ツールの allow_large
  • CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL
  • skills フィールドからのプリロードは最大32個
  • MCP ツール説明文の上限: ツール検索経由は 16,384 字(2.1.295)、既定は 2,048 → 4,096 字(2.1.296)
  • すべて一次情報で確認しました(Claude 側だけの主張)。

A-7. 2.1.301 の修正(10-15) [確認済]

  • LLM ゲートウェイ経由で圧縮が繰り返される問題を修正。
  • /rewind 後にスキルがモデルに提示されなくなる問題を修正。
  • 小さいコンテキストのモデルへ切り替えると、切り替え前のモデルが会話を先に要約するようになりました。
  • 両AIの主張を合わせると、一次情報と一致します。
  • codex が挙げた「大量の引数名による停止」「プレースホルダー展開によるメモリ過剰使用」「/compact 時の UI 停止」は、今回の取得範囲では個別に照合していません。一次確認できていない状態です(誤りという意味ではありません)。

A-8. OpenTelemetry の計測項目追加(2.1.300 / 2.1.301) [確認済]

  • 2.1.300: api_request イベントに cache_creation_5m_tokens と cache_creation_1h_tokens を追加。
  • 2.1.301: tool_decision イベントに classifier_verdict と permission_mode を追加。classifier_category は OTEL_LOG_TOOL_DETAILS=1 のときだけ付きます。
  • codex 側だけの主張でしたが、一次情報で確認しました。

A-9. /usage の警告と /reload-skills の明記(2.1.299) [確認済]

  • /usage で max effort、ワークフロー、常時ロードされるコンテキスト、大きなツール結果について警告が出ます。
  • /reload-skills が、コンパクションで消えたスキル一覧を戻す手段だと明記されました。

A-10. Mods の API 追加(2.1.299〜2.1.301) [確認済]

  • prompt.change、$.ui.view({agentId})、virtualText などが追加されました。agent.spawn でワークフローエージェントの prompt と model も書き換えられます。
  • 「Mods の発表は10/1前後」「サンドボックスなしで動く」という点は、二次報道のみです [要検証]。

A-11. Sonnet 5.5 のキャッシュ読み取り値下げ [確認済]

  • $0.20 → $0.10/M です。API 側は 10-07、Claude Code の表示への反映は 2.1.296 です。
  • Platform release notes と changelog の両方で確認しました。

A-12. Code Review の一般提供開始(10-15) [確認済]

  • Team / Enterprise 向けです。リポジトリごとに Quick / Standard / Deep を選べます。
  • 「約20分 → 6〜10分、約3倍速」は公式の公表値ですが、どの段階(tier)の値かは書かれていません。
  • codex 側だけの主張でしたが、一次情報で確認しました。
  • 出典: https://claude.com/resources/articles/code-review-is-now-generally-available

**B-2. 管理キー isDxt* の削除(破壊的変更、10-13)** [確認済]

  • isDxt → isDesktopExtension への移行が必要です。両AIが一致しています。
  • 一次情報には、両AIが書いていない追加情報があります。macOS プロファイルや Windows のユーザーポリシーが旧キーしか持っていない場合、端末そのものが unmanaged 扱いになります。

B-3. v2.42304.0(10-15) [確認済]

  • Windows でワークスペースの起動がタイムアウトする問題を修正。
  • Code タブでアプリが代行する Git 操作が、リポジトリの Git hooks を実行しなくなりました(バグ修正ではなく挙動変更)。Git LFS は先にターミナルから push する必要があります。
  • クラウドへ移したセッションで、未追跡ファイルが消える問題を修正。
  • 同じ版で、Windows の claude.exe の署名証明書も更新されています(両AIとも未記載)。

B-4. desktopHome と Unified Claude の全組織適用(v2.31226.0 / 10-08) [確認済]

  • Standard のように大文字で書くと off と解釈される点に注意が必要です。
  • Claude 側だけの主張でしたが、一次情報で確認しました。

B-5. Pro / Max の新規 Cowork タスクがクラウド実行に(10-06、対象期間外) [確認済]

今日の注目

  1. MCP 許可ルールの厳密化(A-5)
  • mcp__a のような前方一致を前提にした allow / deny ルールや、エージェントの tools: は、2.1.299 以降で黙って一致しなくなる可能性があります。
  • 本リポジトリの settings とエージェント定義を棚卸しする価値があります。
  1. onFailure: "block" と UserPromptSubmit のタイミング変更(A-3 / A-4)
  • hook は既定で fail-open だという既存知見を、設定で閉じられるようになりました。
  • deny の土台となる安全用 hook に付けるかどうか、実機で確かめる価値があります。
  • updatedInput を返す hook が、未知のキーを捨てられて挙動を変えていないかも併せて確認します。
  1. アイドル時コンパクション(A-1)と 1h キャッシュ前提の整合
  • headless / cron 実行や長時間開いたセッションで発動するかどうかを、2.1.300 の OTel 項目(cache_creation_1h_tokens)で確認します。
  • 既存知見の前提を更新すべきか判断できます。
