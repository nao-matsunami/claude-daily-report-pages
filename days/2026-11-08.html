A. Claude Code(重点)

A-1. v2.1.319:MCP tasks の自動バックグラウンド化

[確認済](両AIが一致し、changelog 原文とも一致)
MCP サーバーがタスクとして実行するツール呼び出しは、すぐバックグラウンドに移り、終わると結果が通知されます。従来どおり完了を待たせたい場合は CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND を設定します。
https://code.claude.com/docs/en/changelog#2-1-319

A-2. v2.1.319:permissions.denyInsteadOfPrompting の追加

[確認済](Claude 単独の主張で、Claude 自身は「changelog では未確認」としていましたが、原文で確認しました)
承認プロンプト待ちになるはずの呼び出しを拒否し、ターンを続けます。適用先はターミナルセッション、サブエージェント、teammates です。原文は "in terminal sessions, subagents and teammates" で、claude -p が対象に含まれるかは明記されていません。
https://code.claude.com/docs/en/changelog#2-1-319

A-3. v2.1.319:自己ペースの /loop が再スケジュールなしで終了するよう変更

[確認済](Claude 単独の主張で、原文で確認)
再スケジュールせずにターンが終わると、そこでループも終了するようになりました。以前は代わりの wakeup が予約されていました。旧挙動に戻すには CLAUDE_CODE_LOOP_KEEPALIVE=1 を設定します。

A-4. v2.1.319:/context 改善、/tasks の「Earlier in this session」、/claude-api latency-optimize、/clear 修正

[確認済](両AIが部分的に一致し、原文で確認)

  • /context:Claude が読む表を短くしました。各リストは上位10行で、オンデマンド読み込みの MCP ツールは呼ばれるまでサーバーごとに1行です。
  • /tasks:終了したサブエージェントを再度開いてメッセージを送れます。再起動後も可能です。
  • /claude-api latency-optimize:追加されました。
  • /clear:バックグラウンドエージェントや teammates の実行中コマンドを止めてしまう不具合を修正しました。

補足として、Claude が書いた「以前は視覚グリッド全体を毎ターン送っていた不具合の修正」という説明は、原文の表現(表を短くする改善)と一致しません。原文は改善として書かれており、不具合修正という位置づけは確認できませんでした。

A-5. v2.1.319:ネストした skills の読み込み変更、PostToolUse の10秒猶予

[確認済](Claude 単独の主張で、原文で確認)

  • Bash サンドボックスが有効なとき、起動ディレクトリより下の .claude/skills は、そこで起動するか /cd したときだけ読み込まれます。
  • PostToolUse hook は、割り込まれたターンの後に完了したツール呼び出しでも、最大10秒の猶予つきで実行されます。

A-6. v2.1.318:バックグラウンドのサブエージェントが3分でシェルをバックグラウンドへ移す

[確認済](両AIが一致し、原文で確認)
全プロバイダが対象で、目的は prompt cache の失効を防ぐことです。codex が書いた「macOS で多数の Bash 実行時に停止・メモリ増大する不具合の修正」は、確認した範囲の原文には見当たりませんでした(一次確認できず)。

A-7. v2.1.317:サブエージェントの effort 継承変更、v2.1.316:CLAUDE_CODE_SUBAGENT_EFFORT

[確認済](両AIが一致し、原文で確認)
メインと別のモデルを使うサブエージェントや teammates は、そのモデルに保存された effort、なければ既定値を使います。2.1.316 では、ほかに指定がないときの値を CLAUDE_CODE_SUBAGENT_EFFORT で決められるようになりました。

A-8. v2.1.317:/design-sync がデザインシステムの移行を事前に検知

[確認済](codex 単独の主張で、原文で確認)
デザインシステムが Claude 側へ移っている場合は、ビルド前にそれを伝えて停止します。以前はアップロード時に失敗していました。

A-9. v2.1.317:アカウントのメールアドレス送信前の確認、Agent SDK の onFailure: "block"、/schedule のコネクタ警告

[確認済](Claude 単独の主張で、原文で確認)

  • 新しい確認:Web やシェルのツールがアカウントのメールアドレスをネットワークに送る前に、ユーザーに確認します。
  • onFailure: "block":hook のコールバックが失敗したら、その操作をブロックします。
  • /schedule:頼んでいないコネクタがクラウドタスクに付いた場合に警告します。

Claude は、メールアドレスが User-Agent に入るという報告(GitHub #107757、v2.1.318)をこの確認機能と結びつけていました。しかし changelog の該当エントリは 2.1.317 で、報告との対応関係は一次確認できていません。

B-4. Enterprise の chat と Cowork の統合:11-16 に自動有効化

[確認済](codex 単独の主張で、管理者ガイドで確認)
設定を変えていない組織では 11-16 に自動で有効になります。条件は、Chat とクラウドのコード実行・ファイル作成の両方がオンになっていることです。事前に「Keep disabled」を選べば有効になりません。ZDR、HIPAA-ready、CMEK を使う組織は対象外です。ページの更新日は「今週更新」としか書かれておらず、正確な日付は一次確認できませんでした。
https://support.claude.com/en/articles/17444462

今日の注目

  1. permissions.denyInsteadOfPrompting(v2.1.319)と、メールアドレス送信前の確認(v2.1.317)を cron の claude -p で試す
  • 2.1.317 で、メールアドレスを送るツール呼び出しの前に「確認する」ステップが入りました。非対話の実行では、ここで止まるか拒否される可能性があります。

  • 再スケジュールしなかったターンでループが終わるようになりました。
  • /loop に頼る自動化は、何もしないと黙って止まるおそれがあります。
  • 影響の棚卸しをして、必要なら CLAUDE_CODE_LOOP_KEEPALIVE=1 を検討してください。
  1. Cowork の期限が続きます(11-10 の desktopHome、11-16 の統合の自動有効化)
  • 2日後の 11-10 に desktopHome の既定値変更が発効します。既存の知見はありますが、保持期間を2つとも設定したかの最終確認が必要です。
  • 管理している Enterprise 組織があれば、11-16 の自動有効化を受け入れるか、オプトアウトするかを決めておく必要があります。
