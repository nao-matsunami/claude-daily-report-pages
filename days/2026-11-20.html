Claude / Anthropic 直近動向：審判まとめ（2026-11-13〜11-20）

一次確認に使ったページ：Claude Code changelog、Desktop/Cowork changelog、Platform リリースノート、Support リリースノート、anthropic.com の IPO と CVP のページ、Support の Unified / Artifacts / Design 管理者ガイド、claude.dev の記事。
入力は codex と Claude の2系統だけです。片方だけが主張し、一次情報でも裏が取れなかったものは [要検証] にしています。

A. Claude Code（最重視）

A-1. sandbox 内の Bash が通常の権限確認を通るように（2.1.325, 11/13）
[確認済]（Claude のみが主張。changelog 原文と一致）
既定で確認を求めるようになりました。従来どおり自動で通すなら sandbox.autoAllowBashIfSandboxed: true を設定します。Desktop v5.11492.5 にも同じ変更があり、「routine can stop at a prompt」と明記されています。
出典: https://code.claude.com/docs/en/changelog / https://claude.com/docs/cowork/changelog

A-2. スケジュールタスクと /loop で、allowed-tools や hooks を宣言した skill を実行前に確認（2.1.325）
[確認済]
無人で動かすには permissions.allow に Skill(name) を追加します。

A-3. Code Mode と agent teams の併用（2.1.326, 11/16）
[確認済]（両AIが一致し、原文とも一致）
Code Mode と agent teams を同時に有効にできるようになりました。すでに Code Mode をオンにしていた場合、teams 有効のセッションは Code Mode で始まります。同じ版で、Desktop の Code タブで managed settings のサブエージェントモデルが効かなかった問題も直りました（codex の主張と一致）。

A-4. 2.1.326 の挙動変更（Claude のみが主張）
[確認済]（4点とも原文と一致）

  • hook の "decision":"block" が効く場面が増えました。常に block を出力している hook は、実際に呼び出しを止め始める可能性があります。
  • plan mode の自動 compaction が、応答しているモデル（opusplan なら Opus）で走るようになり、コストが増える可能性があります。
  • worktree で隔離されたサブエージェントは、共有ブランチを書き換えうる git コマンドを拒否します。
  • /claude-api skill は、既定で Managed Agents 上にエージェントを構築します。

A-5. 2.1.327（11/17）：/status の診断拡充と各種修正
[確認済]（codex の主張。原文と一致）
/status に一覧が出るようになったものは次のとおりです。

  • 壊れた agent / skill / command / output style ファイル
  • keybinding のエラー、使えない sandbox、無視された権限設定
  • 一度もマッチしない hook matcher

修正点は次のとおりです。

  • 同名スキルが / メニューに重複表示され、どれを選んでも最初のものが実行される問題
  • compaction 後、読み込み済みのプロジェクト外ファイルが Edit できない問題
  • Grep の head_limit と offset によるページングで結果が重複・欠落する問題
  • VPN 断などの長い障害の後、リモート MCP が切断されたままになる問題（今は約1日、バックグラウンドで再試行します）

A-6. 2.1.327：auto mode が「任意のパッケージを実行できる allow ルール」を無視
[確認済]
Bash(pnpm dlx *) のようなルールは無視され、安全チェックが判断します。ExitWorktree は、未保存の作業があるかもしれない worktree を削除する前に確認するようになりました。確認の相手がいない場合や don't-ask モードでは拒否されます。

A-7. 2.1.327 のその他（Claude のみが主張）
[要検証]
対象は2点です。

  • 兄弟エージェントのメッセージで再開されたサブエージェントもセッションの権限に従う
  • モデル指定なしのサブエージェントが /model 後の再開でも元のモデルを保つ

今回取得できた changelog の範囲では、この2行を照合しきれていません。不在を確認したわけではなく、一次確認できていないという意味です。

A-8. 2.1.328（11/19）：hooks 関連
[確認済]（両AIが一致し、原文とも一致）

  • mcp_tool hook でも "onFailure":"block" が使えるようになりました。
  • codex が「環境変数を追加」とだけ書いていたものの正式名は CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME です。claude -p --resume / --continue のとき、hook が保留したツール呼び出しを実行させないためのものです。
  • Code Mode のスクリプト出力には、managed のものも含めて UserPromptSubmit hook が走らなくなりました。出力を伏せたい場合は PostToolUse の updatedToolOutput を使います。

A-9. 2.1.328：/code-review の報告範囲を限定し、/simplify に分離
[確認済]（Claude のみが主張。原文と一致）
原文は「on most models」で、/code-review はバグと CLAUDE.md 違反だけを報告します。再利用・簡素化・効率化の提案は /simplify の担当です。

A-10. 2.1.328：claude -p のバックグラウンド待ちを一括10分でカウント
[確認済]
CLAUDE_CODE_FORK_SUBAGENT=0 のとき、バックグラウンドのサブエージェントとそれが待つ子エージェントを合わせて10分の待ち時間で数えます。延ばすには CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS を引き上げます。

A-11. 2.1.328：自動 compaction が古い system prompt を再利用する問題の修正、長大・不正な Markdown での描画フリーズ修正
[確認済]（codex の主張。原文と一致）

A-12. 2.1.323（11/12, 期間外）：Code Mode 本体
[確認済]
CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 で有効になり、対話ターミナル限定です。分類器はコード単位で判定し、PreToolUse には複合コマンドが届くことがあります。
同じ版の「認識できないモデルIDを 1M として扱う」変更も確認済みです。

A-13. 2.1.323 / 2.1.325 の細目（Claude のみが主張）

今日の注目

  1. 2.1.325 で sandbox の自動許可が既定でオフになった件と、Skill(name) の確認（A-1 / A-2）

cron や /loop による無人実行が、確認待ちのまま止まる直接の原因になります。headless で動かしているジョブが sandbox の Bash を使っているか、hooks や allowed-tools を持つ skill を呼んでいるか、実際に流して確認する価値があります。

  1. 2.1.326 の "decision":"block" 適用拡大と 2.1.328 の onFailure: block / CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME（A-4 / A-8）

今まで実質的に効いていなかった block が効き始めるおそれがあります。手元の hooks の中に、常に block を出力するものがないか棚卸しすべきです。deny 床の設計にも関わります。

  1. 2.1.327 の /status 診断（A-5）

一度もマッチしない hook matcher、壊れた skill、無視された権限設定が一覧で出ます。手間がほぼかからず、既存の hooks や skill の棚卸しの答え合わせに使えます。
