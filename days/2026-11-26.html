Claude Code

Claude Ship と /ship（11-23）

[確認済] 両AIが一致し、公式記事とも合っています。

  • 構成は3つです：Code Review（GA、深さは Quick / Standard / Deep）、PR Steward（β、承認やマージはしない、@claude stop で停止）、Claude Approvals（β、リポジトリ内のポリシーファイルに従う、まず observe-only を推奨）。
  • 対象は Team / Enterprise の GitHub リポジトリで、トークン課金です。/ship の実行は通常の Claude Code 使用量に数えられます。
  • ZDR・HIPAA 構成・CMEK の組織では使えません。Enterprise は 2027-01-15 までに $10,000 以上のクレジットを申請できます（Claude のみが記載していましたが、原文で確認しました）。
  • 補足: /ship は changelog 2.1.328〜2.1.332 には見当たりませんでした。記事には「11-23 から Claude Code とデスクトップアプリへ段階提供」とあります。

v2.1.332（11-25）：MCP 由来の skills（β）と PreSkillShellCommand hook

[確認済] 両AIが一致し、changelog 原文とも合っています。

  • MCP サーバーが配る skill が / メニューに server:skill として出ます。
  • PreSkillShellCommand hook で、skill やコマンドが読み込み時に実行するインラインのシェルを拒否できます。2.1.331 以前では、この hook を書いた設定ファイルがあると起動時にダイアログが出ます。changelog

v2.1.332：computer-use が予約スキル名に

[確認済] Claude のみの主張ですが、原文で確認しました。

  • Mac で computer use が有効な場合、同名の自作 skill やコマンドは読み込まれなくなり、起動時に改名を促す通知が出ます。

v2.1.332：compaction・メモリ・hook 出力・Code Mode の安定性修正

[確認済] 両AIが一部ずつ挙げており、全部を原文で確認しました。

  • 「Prompt is too long」で止まる問題を修正しました（自動 compaction が繰り返し失敗した場合）。
  • 要約が出力上限を超え続けたときは、3回打ち切られた後に短い要約を求めるようになりました。
  • リクエストサイズ制限のあるゲートウェイで 413 が続く状態から回復しやすくなりました。
  • EnterWorktree の後に CLAUDE.md と rules が二重送信される問題を修正しました。
  • hook の出力が止まらないときのフリーズを修正しました。約5万字を超える出力は短縮されます。
  • 長い会話の再開時と、ツールの多い MCP での起動時にメモリ使用を改善しました。
  • Code Mode のサブエージェントが10分を超えるスクリプトで「Agent stalled」になる問題を修正しました（codex の「長時間サブエージェント停止」はこれに当たります）。

v2.1.332：単体版 Claude Design から移したデザインシステムの README 修正

[確認済] codex のみの主張ですが、原文で確認しました。

  • 長い README があると、デッキやデザインの作成開始時に読み込むファイル一覧が失われる問題を修正しました。

v2.1.331（11-23）：Code Mode のクラウド基盤対応ほか

[確認済] Code Mode 対応は両AIが一致し、原文とも合っています。

  • Code Mode が Bedrock / Google Cloud's Agent Platform / Foundry / Claude Platform on AWS のターミナルセッションで使えるようになりました。
  • プラグインのマニフェストに optionalDependencies を指定できるようになりました。
  • PermissionDenied hook の retry: true は、ユーザーがその呼び出しを求めていた場合だけ再実行する意味に変わりました。
  • 予告: 11-30 以降、managed の extraKnownMarketplaces は既定で自動更新になります。

v2.1.330（11-20）：/loop と定期タスクを最長30日に

[確認済] 両AIが一致し、原文とも合っています。

  • セッションが動いている間、最長7日から30日に延びました。それより前に作ったタスクは7日のままです。
  • 同じ版に次の変更もあり、すべて原文で確認しました（Claude のみが記載）：
  • model を指定した skill（context: fork を除く）が、サブエージェント・fork・compaction・/recap をセッションのモデルのまま残すようになりました。
  • prompt hook の model にエイリアスを書けるようになりました。
  • HTML コメントを含む CLAUDE.md でリンク参照定義が落ちる問題を修正しました。
  • Enterprise Admin Console で管理された組織へのサインインと、組み込み mod「easel」を追加しました。

v2.1.328 / 2.1.329（11-19）：auto mode 拡大・onFailure・/code-review

[確認済] Claude のみの主張ですが、原文で確認しました。

  • 2.1.328:
  • Bedrock / Agent Platform / Foundry / Claude apps gateway の Opus 4.6・Sonnet 4.6 で auto mode が使えるようになりました。権限モードを指定しない対話セッションは auto mode で始まります。
  • mcp_tool hook に "onFailure": "block" を追加しました。
  • /code-review はバグと CLAUDE.md 違反だけを報告し、指摘を Important / Pre-existing / Nit に分けるようになりました。整理系の指摘は /simplify で出します。
  • 自動 compaction が古いシステムプロンプトを使い回す問題を修正しました。
  • 2.1.329:
  • Code Mode で PreToolUse hook がエラーになっても、スクリプト内のツール呼び出しを拒否しなくなりました。 止める必要がある hook には "onFailure": "block" を明示します。
  • 事前起動されたプロセスでプロジェクトの autoCompactWindow が無視される問題と、settings.json から消した CLAUDE_AUTOCOMPACT_PCT_OVERRIDE が実行中のセッションに残る問題を修正しました。
  • フォルダの hook がどこで宣言されているかを、信頼ダイアログで警告するようになりました。

今日の注目

  1. Code Mode と hook の onFailure（2.1.328 / 2.1.329）
  • 2.1.329 から、Code Mode では PreToolUse hook がエラーになってもツール呼び出しを止めなくなりました。
  • 同じ回で、v7.37095.0 の「macOS ではプラグイン hook が以前止めなかった操作を止め得る」も合わせて試すと効率的です。
  1. PreSkillShellCommand と MCP 由来の skills（2.1.332）
  • MCP サーバーから skill が配られるようになると、そのインラインシェルの実行面が広がります。
  • 2.1.331 以前では、この hook を書いた設定があると起動時にダイアログが出ます。版数が混在する cron 環境では止まる可能性があるので注意が要ります。
  1. 3P 基盤の auto mode 拡大と、ゲートウェイの安全チェックの5分待ち
  • 2.1.328 で、3P 基盤の Opus 4.6 / Sonnet 4.6 でも、権限モード未指定の対話セッションは auto mode で始まるようになりました。
  • Cowork v6.28899.2 では、ゲートウェイの安全チェック結果が返らないと5分待ってターンを終えます。
