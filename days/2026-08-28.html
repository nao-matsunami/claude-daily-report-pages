3つの出力を突き合わせ、主要項目を一次情報で確認しました。以下、確度ラベル付きでまとめます。

A. Claude Code（CLI）

A-1. promptCacheTtl / subagentPromptCacheTtl（v2.1.242 以降・changelog は v2.1.243 / 8-25）

[確認済] メイン会話と「それ以外（サブエージェント・ワークフロー・fork・compaction・セッションタイトル）」の 2 バケットにそれぞれ 5m / 1h を指定できる。設定と環境変数（CLAUDE_CODE_PROMPT_CACHE_TTL / CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL）の両方が存在し、両方とも v2.1.242 以降が必要。優先順位は FORCE_PROMPT_CACHING_5M=1 > バケットの環境変数 > 設定 > ENABLE_PROMPT_CACHING_1H=1 > 既定値。既定は「Claude サブスク内ならメイン会話 1h・それ以外 5m」「クレジット/APIキー/クラウドプロバイダは両方 5m」。

  • Gemini の「env 変数あり」「サブエージェントも 1h に延長可」はいずれも一次情報と一致。Claude の「メインだけ 1h・サブは 5m」は changelog の表現で、docs 上はサブ側も 1h に設定可能。
  • 出典: https://code.claude.com/docs/en/prompt-caching#cache-lifetime / https://code.claude.com/docs/en/changelog

A-2. Auto mode タブ（/permissions）と Bash ワイルドカード allow ルールの起動時警告（v2.1.246 / 8-25）

[確認済] /permissions に auto mode の classifier ルールを閲覧・編集するタブが追加。Bash(git * main) のようにサブコマンドより前にワイルドカードが来る allow ルールは、挿入されたオプションにもマッチするため起動時警告が出る。

  • Gemini は日付を 8-26 としているが、公式 changelog は 8-25。
  • 出典: https://code.claude.com/docs/en/changelog

B. Claude Cowork / Claude アプリ

B-1. Cowork の組み込みブラウザ（8-26）

[確認済] デスクトップアプリ内で Claude 専用ブラウザを開き、閲覧・クリック・フォーム入力を行う。個人のブラウザとは完全分離（タブ・ブックマーク・パスワードを見ない／Chrome・Edge・Firefox からのログイン取り込みは任意）。銀行・メール・SSO サイトは既定で除外。Pro/Max/Team に今週ロールアウト、macOS/Windows/Linux（beta）、Enterprise は管理設定で即有効化。プロンプトインジェクションについて「同じリスクがあり、セーフガードでも排除はできない」と明記。

  • 出典: https://claude.com/blog/cowork-built-in-browser

[棄却] Gemini の「Chrome サイドパネル連携も強化」は誤り。今回の機能は Chrome ではなく Claude 独自の分離ブラウザで、既に開いているページを扱うなら Claude in Chrome を使え、という位置づけ。Chrome 拡張の話と混同しています。

B-2. Memory がチャットと Cowork で共通化（8-25）

[確認済] 3 AI すべてが言及。会話中に更新され、トピック単位のファイルとして閲覧・編集・削除可。健康・信条などのセンシティブ領域は既定で保存されず、明示的にオンにしたときだけ保存され、保存のたびに通知。Free/Pro/Max は既定オン、Team/Enterprise は管理者制御（かつユーザーが有効化するまでオフ）。

  • 出典: https://claude.com/blog/claudes-memory-works-everywhere-and-you-decide-whats-in-it / https://support.claude.com/en/articles/12138966-release-notes

B-5. レッドチーム攻撃成功率の数値

[棄却（Claude の要約に誤りあり）] 一次情報の正しい対応は次のとおり。

  • セーフガードなし: Opus 4.5 = 17.6%、Opus 5 = 3.8%
  • probes + safety classifier あり: Sonnet 5 = 0%、Opus 5 = 0%、Fable 5 = 0.3%

Claude の出力にあった「Opus 5 + セーフガード 3.8%（セーフガードなしは 17.6%）」は誤り。17.6% は Opus 4.5 の値であり、3.8% はセーフガード適用前の Opus 5 の値です。

  • 出典: https://claude.com/blog/claude-in-chrome-generally-available

今日の注目

  1. promptCacheTtl / subagentPromptCacheTtl（A-1） — 唯一、今週の更新で運用コストに直接効く設定で、かつ一次ドキュメントが優先順位規則まで明文化しています。特にこのリポジトリのような headless / cron / サブエージェント多用の構成では、「それ以外」バケットが既定 5m のままキャッシュを取り逃している可能性が高い。CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL=1h を入れる／入れないで cache_read_input_tokens 比を実測する価値があります。v2.1.242 以降が必要な点と、FORCE_PROMPT_CACHING_5M=1 が全てを上書きする点だけ先に確認を。
  1. Cowork 組み込みブラウザ + Claude in Chrome GA（B-1 / B-4） — Cowork は重点領域で、かつ「承認なしの自律ブラウザ操作」が既定挙動に入ってきたため、権限設計の棚卸しが必要なタイミングです。銀行・メール・SSO の既定除外や、Chrome とは別物である点（Gemini が誤っていた箇所）を踏まえて、どちらを使うかの方針を決めておく価値があります。
  1. /claude-api cost-optimize と /usage の Loops 内訳（A-3 / A-4） — 1 と組み合わせると効果測定のループが閉じます。/loop を定期実行に使っている構成なら、Loops 内訳で「1 回あたりトークン」が見えるようになったのが実利的。cost-optimize は「1 変更ずつ計測する」設計なので、上の TTL 変更の効果検証にそのまま使えます。
