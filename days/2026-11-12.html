1. Claude Code(重点)

v2.1.319(11/6):/context の送信内容を縮小

[確認済] 両AIが一致し、changelog 原文とも合っています。/context の表示グリッド全体が後のターンでも毎回送られていた不具合が直りました。あわせて、各リストは大きい順の上位10行に絞られ、まだ呼ばれていない遅延ロード MCP ツールはサーバーごとに1行にまとめられます。
出典: https://code.claude.com/docs/en/changelog

v2.1.319:MCP タスクをバックグラウンドで実行

[確認済] 両AIが一致し、原文とも合っています。MCP サーバーが task として実行するツール呼び出しは、すぐにバックグラウンドへ回され、終わると結果が通知されます。従来どおり待たせたい場合は CLAUDE_CODE_DISABLE_MCP_TASK_BACKGROUND を設定します。原文にはもう一つ、CLAUDE_CODE_DISABLE_MCP_TASKS=1(MCP タスク自体を無効化する)もありました。これは両AIとも書いていません。
出典: 同上

v2.1.319:claude -p が拒否時に終了コード1を返す/auto mode がサーバー確認なしで続行しない

[確認済] codex の主張で、原文とも合っています。auto mode で安全確認が使えずに操作が拒否された場合、これまでは終了コード0でしたが、text 出力・JSON 出力とも1を返すようになりました。cron や CI で失敗を検知する仕組みに影響します。auto mode がサーバー側の確認なしに処理を続けなくなった件と、cron 実行の権限モードへの影響は検証済みです。
出典: 同上

v2.1.319:permissions.denyInsteadOfPrompting を追加

[確認済] Claude の主張で、原文とも合っています。許可待ちになるはずのツール呼び出しを拒否し、そのままターンを続けます。ターミナルのセッション、サブエージェント、チームメイトに効きます。

  • 「値は boolean でなければならない」という点は [要検証] です。Classmethod の二次情報だけで、原文には型の記述がありません。
  • 「AskUserQuestion や plan mode が使えなくなる」は Claude による推論で、一次確認はできていません。

出典: 同上 / https://dev.classmethod.jp/articles/20261108-cc-updates-v2-1-319/

v2.1.319:/loop は次の予約がなければ終了(CLAUDE_CODE_LOOP_KEEPALIVE=1 で従来動作)

[確認済] 原文と合っています。

v2.1.319:sandbox 有効時のサブフォルダ skills//tasks の「Earlier in this session」//claude-api latency-optimize

[確認済] Claude の主張で、原文とも合っています。

v2.1.321:skills の読み込み変更/headless での mod 再読み込み/Cowork の PostToolUse 制限/長い通知の省略

[確認済] Claude の主張で、原文とも合っています。

  • ~/.claude/plugins の中にある .claude/skills は読み込まれなくなりました。

  • Cowork のクラウドセッションでは、PostToolUse hook が AskUserQuestion の回答や ExitPlanMode のプランを書き換えられなくなりました。
