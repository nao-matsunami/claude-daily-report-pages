1. Claude Code(最重視)

Code Review の一般提供(GA)

[確認済] 2026-10-15 に GA になりました。対象は Team / Enterprise で、管理者がリポジトリごとに Quick / Standard(既定)/ Deep を選べます。「約3倍速い(約20分 → 6〜10分)」は Anthropic 自身の数字で、第三者の計測ではありません。

  • codex が示した claude.com/resources/articles/... という URL は今回開いていません。中身を確認したのは下の blog URL です。
  • 出典: https://claude.com/blog/code-review-is-now-generally-available

Idle compaction(v2.1.299)と /config のトグル(v2.1.302)

[確認済] ターミナルで20万トークン以上の会話を約54分放置すると、1時間のキャッシュが切れる前に自動で圧縮します。

  • 圧縮を始める下限は CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS で変えられます。
  • 止めるには settings.json に "idleCompaction": false を書きます。v2.1.302 で /config にもオン/オフの行が加わりました。
  • 2つの AI の記述は一致しています。

fork サブエージェントの既定有効化と、Desktop/VS Code でのバックグラウンド実行(v2.1.302)

[確認済] fork サブエージェントが claude -p、Agent SDK、Desktop、VS Code でも既定で有効になりました。無効にするには CLAUDE_CODE_FORK_SUBAGENT=0 を設定します。

  • Desktop と VS Code では、メイン会話から起動したサブエージェントが常にバックグラウンドで動きます。

-

prompt/agent hooks の同時実行は1イベントあたり最大12件(v2.1.302)

[確認済] 2つの AI が一致しており、changelog の原文「At most 12 of one event run at a time」とも合っています。

MCP の allow ルールがサーバー名の完全一致になった(v2.1.299)

[確認済] mcp__a と書いても、a__b や a_ という名前のサーバーには効かなくなりました。mcp__<server>__* の形で書く必要があります。

UserPromptSubmit hook が skill / コマンドの展開より前に動く(v2.1.299)

[確認済] Claude の出力だけが挙げていましたが、changelog で確認できました。この hook でブロックすると、skill やコマンドに埋め込まれたシェルコマンドも実行されません。

hook が返す updatedInput の検証(v2.1.300)

[確認済] PreToolUse / PermissionRequest hook が返す入力を、Claude 自身の入力と同じように検証するようになりました。未知のキーは捨てられ、ツールが受け付けない入力なら呼び出しは拒否されます(changelog で確認)。

Write ツールが UTF-8 以外のファイルへの書き込みを拒否する(v2.1.299)

[確認済](ただし範囲は Claude の書き方より狭い) changelog での扱いはバグ修正です。以前は Windows-1252 / Shift-JIS / GBK / UTF-16BE のファイルを黙って UTF-8 に変換していましたが、今は書き込みを拒否します。「UTF-8 以外をすべて拒否する」とは書かれていません。

OTel の cache_creation_5m_tokens / cache_creation_1h_tokens(v2.1.300)

[確認済] 2つの AI が一致しており、changelog でも確認できました。OpenTelemetry の api_request イベントで、キャッシュ書き込みがキャッシュの寿命(5分/1時間)ごとに分かれました。

v2.1.300 の修正(SessionEnd hooks と自動ツール検索)

[確認済](codex の書き方は広すぎる) どちらの修正も実在します。

  • SessionEnd hooks の修正は、正確には「バックグラウンドのコマンドが動いている間に終了すると、ときどき実行されない」問題の修正です。終了時に常に動かなかったわけではありません。
  • ENABLE_TOOL_SEARCH=auto が会話の途中で切れる問題も修正されています。

v2.1.301 の skills / コマンド / hooks の負荷修正

[確認済] codex だけが挙げていましたが、changelog で確認できました。

  • 引数名が多い・長い場合の数秒の停止(先頭64個、各64文字までしか埋めないようになった)
  • プレースホルダー展開による大量のメモリ消費
  • /rewind の後に skills がモデルに提示されなくなる問題
  • ゲートウェイの応答が別のモデル名を返す環境で、圧縮が繰り返される問題

v2.1.302 の起動・キャッシュ・課金まわりの修正

[確認済] 次の4点を changelog で確認しました。

  • プラグインが多いときの起動の高速化(特に Windows)
  • ToolSearch で読み直したとき、または圧縮後に、セッション途中で追加したツールがキャッシュミスを起こす問題の修正
  • 利用クレジットで課金された回答の後に、プロンプト提案を出さないようにした修正
  • クラウドセッションを再開すると費用・使用量の表示がゼロに戻る問題の修正

v2.1.303

[確認済] 内容は「Bug fixes and reliability improvements」だけで、個別の変更は書かれていません。

v2.1.304 の追加・変更

[確認済] 以下を changelog で確認しました。

  • 圧縮した後に skill 一覧を送り直すようになり、/reload-skills は新規・変更分だけを送るようになりました。
  • Pro/Max で、放置した会話を再開すると5時間枠をかなり使う場合に警告が出ます。
  • 1つのソースの skill が登録できる hook は、1セッションあたり1,024件まで、matcher は16,384文字までになりました。

「圧縮サマリーにツール名が残る(Ctrl+O で表示)」は今回の照合範囲外で、確認していません。

auto mode 関連の環境変数

[確認済]

  • CLAUDE_CODE_AUTO_MODE_MODEL(v2.1.302): changelog によると、クライアント側の分類器のモデルだけを変えます。サーバー側の auto mode のモデルは変わりません。
  • CLAUDE_CODE_RETRY_WATCHDOG_MAX_USAGE_LIMIT_WAIT_MS(v2.1.301): 無人実行中に使用量上限に達し、リセットまで遠すぎる場合は待たずに終了します。

vim モードの % モーションは今回照合していません。

その他の v2.1.299 の項目(Claude の出力だけが挙げたもの)

[確認済]

  • CLAUDE_CODE_DISABLE_FILE_MENTIONS: @ でファイルを指定すると、中身ではなくパスだけを渡します。
  • ファイル名やフォルダ名に不可視文字・方向制御文字・< > を含む skill は提示されなくなりました。changelog の言い方は「読み込まれない」ではなく「提示されない(no longer offered)」です。

今日の注目

  1. hooks の挙動が一斉に変わった点を棚卸しする
  • 対象は、v2.1.299 の UserPromptSubmit の実行順の変更、v2.1.300 の updatedInput の検証、Windows で shell 指定のない PreToolUse hook が失敗時にブロックするようになった点(Claude Code v2.1.299 / Cowork 3P)です。
  • 既存の hook の棚卸しの前提が変わります。未知のキーを返している hook は、今は黙ってキーを落とされます。
  • 理由: 気づかないうちに挙動が変わるので、事故が起きやすいからです。
  1. Write ツールが Shift-JIS などへの書き込みを拒否するようになった点(v2.1.299)
  • 日本語環境では、既存の Shift-JIS や Windows-1252 のファイルを自動化で上書きしていると、そこで失敗するようになります。
  • 対象ファイルを grep などで洗い出しておく価値があります。
  1. Claude Design 単体版の終了(12/14)に向けた移行計画
  • 今すぐ移行できるのはデザインシステムだけです。プロジェクトの移行方法はまだ発表されていません。
  • チャットとコメントは終了後に削除されるので、必要なものは書き出しておく必要があります。
  • 理由: 期限が決まっていて、失ったものを取り戻せないからです。
