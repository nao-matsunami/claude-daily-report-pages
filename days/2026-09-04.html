B. Claude Code（最重視）

B-1. v2.1.259（2026-09-02）

[確認済] 3AI 一致、changelog 原文で全項目確認。

  • managedMcpServers 管理設定（HTTP/SSE のみ、command 実行型はスキップ）
  • --permission-prompts none（無人ヘッドレス向け。プロンプトが出る操作は自動 deny、permission mode 自体の判断は生きる）
  • glab mr create/merge/close/reopen/note/update 認識、claude plugin validate --json
  • allowedMcpServers の対象がユーザー追加サーバのみに変更 — 従来 allowlist で弾かれていた managed-mcp.json のサーバがアップグレード後に読み込まれる（止めるには deniedMcpServers）
  • managed settings が読めない場合は黙って無視せず起動拒否
  • https://code.claude.com/docs/en/changelog

補足（今回の追加発見）: --permission-prompts は changelog には明記されていますが、CLI reference（/docs/en/cli-reference）にはまだ掲載されていません。ドキュメント反映待ちの可能性があり、非対話運用に入れる前に実機確認が要ります。

B-2. v2.1.257（2026-09-01）

[確認済] changelog 原文で確認。Fable 5.1 追加、CLAUDE_CODE_SUBAGENT_MODEL_FORCE、/effort の s、auto mode の Containment Escape ルール、作業ディレクトリ外 read の初回確認と permissions.blockReadsOutsideWorkingDirectories、timeFormat/timeZone。

  • 破壊的変更: defaultMode: "bypassPermissions" はプロジェクト settings では無視、--add-dir 系がネットワークパス拒否
  • キャッシュ関連: advisor model 設定時のバックグラウンドリクエストのキャッシュミス、スクリーンショット多用セッションの毎ターン miss、Remote Control 途中接続時の Bash ツール定義再送を修正。/fork が元会話の prompt cache を引き継ぐように変更
  • gateway 経由では fable/best は当面 Fable 5 に解決されたまま（/model で明示選択が必要）
