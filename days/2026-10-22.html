Claude/Anthropic 直近の動き 審判まとめ(2026-10-22)

確認方法: 次の一次ソースを今日取得し、本文を確認しました。code.claude.com/docs/en/changelog、platform.claude.com/release-notes、claude.com の Duet / Code Review GA / Claude Security の各記事、anthropic.com/news と「independent evaluators」の記事です。
情報源について: 収集は codex と Claude の2系統だけです。片方だけの主張は、一次で確認できたものだけを [確認済] にしています。

A. Claude Code(最重要)

A-1. fork サブエージェントが claude -p・SDK・Desktop・VS Code で既定 ON(v2.1.302) — [確認済]
両方の AI が同じ内容を報告しており、changelog 原文とも一致しました。無効化は CLAUDE_CODE_FORK_SUBAGENT=0 です。
出典: https://code.claude.com/docs/en/changelog

A-2. claude -p で権限モードを指定しないと default で起動する場合がある(v2.1.302) — [確認済]
条件は、サードパーティプロバイダ利用時、テレメトリ無効時、新規インストール時のいずれかです。--permission-mode auto を付ければ auto のままになります。Claude は本文で、codex は Qiita 紹介の中で触れており、changelog 原文とも一致しました。
出典: 同上

A-3. Idle compaction(v2.1.299 で追加、v2.1.302 で /config から切替可能に) — [確認済]
200K トークンを超える会話を約54分放置すると compaction が走ります。最小トークン数は CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS で変えられ、"idleCompaction": false で無効化できます。changelog 原文と一致しました。

A-4. prompt / agent hooks の同時実行は同一イベントで最大12件(v2.1.302) — [確認済]
両方の AI が報告しており、原文とも一致しました。12件を超えた分は順番待ちになります。

A-5. compaction 後にスキル一覧を再送し、/reload-skills は差分だけ送る(v2.1.304) — [確認済]
両方の AI が報告しており、原文とも一致しました。なお 2.1.299 の時点では「/reload-skills は全量を再送する」と書かれており、2.1.304 で差分方式に変わっています。

A-6. 休眠会話の再開時に5時間枠の警告を表示(v2.1.304、Pro/Max) — [確認済]
codex だけの主張ですが、原文で確認できました。

A-7. /auto-mode-setup の追加(v2.1.304) — [確認済](一部 [要検証])
プロジェクトと最近のセッションを読み、auto mode の設定を対話形式で支援します。Bedrock、Vertex、Foundry、テレメトリ無効時でも使えます。Claude が書いた「Code Review のレベルにも対応」の部分は、今日の取得範囲では確認できませんでした。

A-8. VS Code で SessionStart hook の実行時間を起動タイムアウトから除外(上限10分、v2.1.304) — [確認済]
codex だけの主張ですが、原文と一致しました。

A-9. ToolSearch 関連の不具合(v2.1.304 / 305) — [確認済]

  • 2.1.304 で、カスタム ANTHROPIC_BASE_URL の背後でも tool search が既定 ON になりました。
  • 2.1.305 で、tool search を拒否するゲートウェイや Vertex / Bedrock で全リクエストが失敗する問題を修正しました。原文ではこれを「2.1.304 のリグレッション」と明記しています。

codex の要約は原文と一致しました。ゲートウェイ経由の環境で 2.1.304 を使っている場合は影響を受けます。

A-10. 「prompt is too long」の誤表示と不要な compaction の修正(v2.1.306、MCP ツールが多いセッション) — [確認済]
両方の AI が報告しており、原文とも一致しました。

A-11. allowedMcpServers の挙動変更(v2.1.305) — [確認済]
managed-mcp.json の stdio サーバーのうち、${VAR} を env にだけ使っているものは allowlist のフィルター対象から外れます。そのため、更新後に読み込まれるようになる可能性があります。読み込ませたくない場合は deniedMcpServers で止める必要があります。codex だけの主張ですが、原文と一致しました。

A-12. MCP 許可ルールの厳密化(mcp__a は a__b にマッチしない) — [確認済]
Claude はこれを「版数未確認」と書いていましたが、原文で v2.1.299 と確定しました。

A-13. hooks / subagent 関連の変更(2.1.295〜2.1.304) — [確認済]

  • onFailure: "block"(2.1.295)
  • subagent がプリロードするスキルは最大32個(2.1.295)
  • subagent の autoCompactWindow(2.1.296)
  • updatedInput の厳密検証(2.1.300)
  • スキルの出所ごとに hooks は最大1,024個(2.1.304)
  • CLAUDE_CODE_AUTO_COMPACT_WINDOW が k / M サフィックスを受け付け、200k が 100K 扱いになる問題を修正(2.1.304)

今日の注目

  1. v2.1.305 の allowedMcpServers の挙動変更(A-11)

更新しただけで、これまで止まっていた MCP サーバーが読み込まれる可能性があります。deny 床を前提にしている構成なら、managed-mcp.json を棚卸しし、必要なら deniedMcpServers を追加する価値があります。

  1. API 2026-10-21 と SDK のメジャー更新(D-1 / D-2)

SDK を ^ 指定で入れている自動化は、更新したときに新しい API バージョンと SDK 自体の破壊的変更を同時に受けます。サンプリングパラメータが 400 になるか(D-2)は未確認なので、移行ガイドの該当節を一次で読み込む検証タスクにするのが妥当です。

  1. v2.1.304 のリグレッションと、compaction 後のスキル再送(A-9 / A-5)

ゲートウェイ経由の環境で 2.1.304 を使っていると、全リクエストが失敗する可能性があります。その場合は 2.1.305 以降が必須です。あわせて、スキルの多いこのリポジトリの cron 運用で、compaction 後にスキルが使えるようになったかと、hooks の1,024個上限に引っかからないかを確認する価値があります。
