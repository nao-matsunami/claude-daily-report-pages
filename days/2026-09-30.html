5. 運用の知見

Prompting Claude Opus 5.5(公式ガイド)

[確認済] 収集にあった項目はすべて原文で確認しました。

  • medium で Opus 5 の high と同等以上の結果が出る
  • xhigh と max は品質向上を測定で確認できた場合だけ使う
  • top-level の effort を変えるとキャッシュが無効になるので、per-message effort(beta)を使う
  • 「よく考えて」系の指示は削除する
  • テキストだけで終わったターンは途中報告として扱い、自動の続行指示は2〜3回までにする
  • elapsed 340s / 1200s のように経過時間を伝える
  • <pasted_content id> で貼り付けテキストを囲む
  • フロントエンドでは避けたいパターンを具体的に挙げる

原文での追加の注意もあります。「思考は max_tokens に含まれるので 128k を推奨」とされています。また、無人実行向けの指示を追記する場合は、セッションの最初のリクエストから入れるよう書かれています。途中で入れると、それまでの思考ブロックが無効になるためです。
出典: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5

収集外だが、一次確認の途中で見つけた項目(参考・changelog 原文で確認済)

  • 2.1.281: CLAUDE_CODE_AUTO_MODE_SERVER が Anthropic API への直接接続にも適用されるようになりました。 2.1.282 では、telemetry がオフのとき、既定でサーバー側の classifier を使うようになっています。
  • 2.1.281: 無人セッションでの危険な rm の確認が変わりました。 対象は --dangerously-skip-permissions と auto mode です。確認が2分待っても答えられなければ、書き換えのヒント付きで拒否されます(CLAUDE_CODE_DISABLE_DANGEROUS_RM_TIMEOUT=1 で無効化できます)。
  • rm -rf "$(pwd)" のようにコマンド置換だけを対象にした削除は、Bash の allow ルールがあっても確認を求めるようになりました。
  • 2.1.281: Self-hosted runner はシステムプロンプトをファイルで渡すようになりました。 --append-system-prompt を後から付け足すラッパーは、--append-system-prompt-file への移行が必要です。

今日の注目

  1. auto mode のサーバー側 classifier の既定化と、危険な rm の2分タイムアウト(2.1.281 / 2.1.282)
  • headless の cron 実行で、権限の判定経路と課金が既存の knowledge とずれている可能性があります。
  • 無人セッションが止まらずに進むようになった分、拒否されたときの挙動も変わります。
  • 既存の knowledge 2件の再検証を最優先にしたいです。
  1. fork サブエージェントが権限モードを引き継ぐよう修正、claude -p での fork の修正(2.1.285)、公式の「無人実行」ガイド
  • fork が plan mode から抜けられなくなった点と、テキストだけで終わったターンを完了扱いしない点を、実際の自動化で確認する価値があります。
  1. Cache diagnostics の正式版化(09-23)
  • レスポンスに常に diagnostics が入るので、レスポンスを厳密に解析している箇所の影響を確認する必要があります。
  • 同時に、beta ヘッダーなしでプロンプトキャッシュの効果を測れるようになりました。
