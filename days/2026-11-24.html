A. Claude Code(重点)

A-1. MCP ツール型フックに onFailure: "block"(v2.1.328)

[確認済]
mcp_tool フックにも "onFailure": "block" が加わり、command・HTTP フックと同じ扱いになりました。フック呼び出しが失敗すると、その操作は止まります。両AIとも主張しています。fail-open/closed の既存知見に関わる変更です。
出典: https://code.claude.com/docs/en/changelog

A-2. Code Mode で、エラーになった PreToolUse フックが拒否しなくなった(v2.1.329)

[確認済](Claude のみが主張。原文で確認)
Code Mode 外と同じ挙動にそろえる変更です。PreToolUse フックがエラーになっても、スクリプトのツール呼び出しは拒否されなくなりました。必ず拒否させたいフックには "onFailure": "block" を付ける必要があります。Code Mode を使っている場合、deny 床の前提が変わります。
出典: https://code.claude.com/docs/en/changelog

A-3. /tasks に予約タスク・/loop・goal・fork を表示(v2.1.329)

[確認済]
/tasks に、このセッションの予約タスク、/loop の起動予定、goal、fork が表示されるようになりました。x を押すと、確認のうえ止められます。同じ版で、管理設定のフックが読み込めなかったときに Desktop など非対話ホストで警告が出るようになり(codex のみが主張、原文で確認)、macOS で繰り返しサインアウトされる不具合も直りました。
出典: 同上

A-4. /loop・繰り返し予約タスクの期間を 7日→最大30日に(v2.1.330 / Cowork v6.28899.6)

[確認済]
期間が延びるのはセッションが動いている間だけです。この版より前に作ったタスクは7日のままです。Cowork 側でも同じ変更があり、scheduledTasksEnabled: false を設定すると、次にセッションを起動したときから全予約タスクが止まります。
出典: changelog / https://claude.com/docs/cowork/changelog

A-5. model 指定付き skill の適用範囲を変更(v2.1.330)

[確認済]
context: fork 以外の skill では、サブエージェント、fork、compaction、/recap がセッションのモデルで動くようになりました。両AIの主張は一致しています。
出典: changelog

A-6. 長い会話の compact 直後のフリーズ・WebFetch のフリーズを修正(v2.1.330)

[確認済](codex の表現の一部に限定条件が抜けています)
原文には次の修正があります。

  • 非常に長い会話を compact した直後に、最大数分固まる問題
  • WebFetch がページによって数分固まる問題
  • パス限定 rules や Read 拒否ルールのあるプロジェクトで、数百ファイルを読んだ後に長く止まる問題

ただし3つ目は Code Mode に限った修正です。codex は「大量ファイル処理全般」のように書いていますが、そこまでは言えません。
出典: changelog

A-7. その他の v2.1.330 修正

[確認済]

  • claude -p --continue で、SessionStart フックが設定した環境変数が失われる問題を修正
  • あるサブエージェントの終了時に、共有している MCP サーバーまで止まる問題を修正
  • HTML コメントを含む CLAUDE.md で、リンク参照定義が消える問題を修正
  • rm の承認対象を拡大(答える人がいない環境では拒否)
  • prompt フックの model に別名(haiku など)を使えるように
  • 組み込み mod「easel」を追加

-p --continue と rm の変更は、cron 運用に直接関わります。
出典: changelog

A-9. v2.1.328 の auto mode を Bedrock・Vertex 等へ拡大

[確認済](Claude の要約には限定条件が抜けています)

出典: changelog

今日の注目

  1. v2.1.329 の Code Mode で、エラーになった PreToolUse フックが拒否しなくなった件(A-2)
  1. v2.1.330 の -p --continue での SessionStart 環境変数の修正と、rm 承認の拡大(A-7)

headless の cron で --continue や rm を使っていれば、挙動が直接変わります。環境変数の受け渡しが実際に直ったかの実機確認と、無人環境で rm が「拒否」になる箇所の洗い出しをおすすめします。

  1. 11/30 以降の extraKnownMarketplaces 既定自動更新(A-8)と、Cowork の PostToolUse 不発火(B-4)

どちらも気付かないうちに供給元やログの前提が変わる種類の変更です。管理設定でマーケットプレイスを固定しているなら、11/30 より前に "autoUpdate": false を付けるかどうかを決める必要があります。
