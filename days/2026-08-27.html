A-3. プロンプトキャッシュ公式ドキュメントの内容

[確認済] Claude が挙げたキャッシュ運用知見は、ほぼ全項目が公式ページの原文と一致した。特に確認できた要点:

  • 値は 5m / 1h のみ、v2.1.242 以降が必要、環境変数は CLAUDE_CODE_PROMPT_CACHE_TTL / CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL
  • 優先順位 FORCE_PROMPT_CACHING_5M=1 > バケット環境変数 > バケット設定 > ENABLE_PROMPT_CACHING_1H=1 > 既定
  • 既定表（サブスク枠内: メイン会話 1h／それ以外 5m、usage credits・API キー・クラウドプロバイダ: 両方 5m）、プラン超過で usage credits に入るとメイン会話も 5m に落ちる
  • Claude apps gateway では 1h TTL 利用不可、Bedrock はモデル/リージョン依存
  • 「メイン会話」バケットには非対話 -p 実行と Agent SDK ターンも含まれる（Claude の要約では明示されていなかった点）
  • 壊す/壊さないの分類、/rewind は既にキャッシュ済み prefix に戻る、fork は親のキャッシュを読むがサブエージェントは読まない、キャッシュのスコープは「マシン＋ディレクトリ」で worktree 間は共有しない — すべて原文どおり

出典: https://code.claude.com/docs/en/prompt-caching

今日の注目

1. promptCacheTtl / subagentPromptCacheTtl（v2.1.243）— 検証パイプラインへの実効性が最も高い

公式ドキュメントで「メイン会話バケットには非対話 -p 実行も含まれる」「サブエージェント・workflows・fork・compaction は既定 5 分」が明記された。毎朝の cron で claude -p からサブエージェントを起動している構成では、サブエージェント側だけが 5 分 TTL で冷えている可能性がある。subagentPromptCacheTtl: "1h" の効果は statusline の cache_creation_input_tokens / cache_read_input_tokens で実測できる。

2. v2.1.246 のサブエージェント maxTurns partial マーク

maxTurns で打ち切られたサブエージェントが、これまで「完了したように見えていた」ものが partial として明示され、SendMessage での継続ヒントが付くようになった。検証ワーカーを非対話で回す構成では、打ち切りを完了と誤認して不完全な検証結果を knowledge に書く事故が起こり得た箇所であり、挙動変化の確認価値が高い。併せて /cd の即時反映（設定・hooks・skills・agents がセッション再起動なしで有効化）も、複数リポジトリを跨ぐワーカーの前提を変える。

3. Bash 権限ルールのワイルドカード警告（v2.1.246）

Bash(git * main) のようにサブコマンド前にワイルドカードを置く allow ルールに起動時警告が出るようになった。理由は「サブコマンドの前に挿入されたオプションにもマッチしてしまう」ため。自リポジトリの permissions.allow にこの形のルールがあるかの棚卸しは、grep 一発で終わる低コスト作業でありながら、権限が意図より広い箇所を実際に見つける可能性がある。加えて非対話 cron 起動で警告がどう出るか（ノイズになるか）も確認しておく価値がある。
