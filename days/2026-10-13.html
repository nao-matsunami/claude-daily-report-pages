A. Claude Code(最重視)

A-1. hooks に onFailure: "block" を追加(v2.1.295 / 10-08)

[確認済]
command / HTTP hooks が起動できない、タイムアウトする、想定外の終了コードで終わる、のいずれかの場合に操作をブロック(fail-closed)できるようになりました。オプトインの追加機能なので、既定は fail-open という既存知見とは矛盾しません。ただし知見に追記が必要です。
出典: https://code.claude.com/docs/en/changelog

A-2. 指示文で書いた prompt / agent hooks がブロックすべき操作を通す問題を修正(v2.1.294 / 10-08)

[確認済]
「Block commands that…」のように指示文の形で書いた hook が、本来止めるべき操作を通してしまう問題の修正です。同じ版で、Stop / SubagentStop の prompt hook の判定も改善されています(早期停止しにくくなる方向)。
出典: changelog(同上)

A-5. skill の allowed-tools / effort が失われる問題を修正(v2.1.295)

A-7. サブエージェント個別の autoCompactWindow と CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL(v2.1.296 / 10-09)

[確認済]
autoCompactWindow はサブエージェントの frontmatter と --agents で指定でき、メイン会話より早く自動 compact させられます。CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL は workflow 用エージェントのモデルだけを統一し、他のサブエージェントのモデルは変えません。
出典: changelog

今日の注目

  1. hook の fail-closed 化(A-1)と prompt hook の修正(A-2)

既存知見では「hooks は timeout 時に fail-open」と確定しています。その弱点を、onFailure: "block" で設定によって塞げるようになりました。deny 床のように、セキュリティ目的の command hook がある場合は付けるべきです。あわせて、指示文で書いた prompt / agent hook が 2.1.294 以前だと素通りしていた可能性があるので、棚卸しする価値があります。

  1. WebSearch 上限の仕様変更(A-14)と、-p で skill の権限が落ちる問題の修正(A-5)
  1. Haiku 5.5 を調査系サブエージェントに使い、サブエージェント個別の autoCompactWindow を設定(D-1・A-7)

コスト削減とメイン会話の負担軽減を同時に試せます。ただし、二次情報(E-2)では「安いモデルにしても速くなるとは限らない」と報告されています。既存知見 subagent-model-env-autocompactwindow-spec-check.md の更新も兼ねて、手元で費用と時間を測ることを勧めます。

単体の Claude Design を使っている場合は、12-14 の終了までにデザインシステムの移行(C-2)も必要です。
