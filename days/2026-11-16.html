前提: 情報源は ChatGPT(codex) と Claude の2系統だけです。2系統が一致しただけでは [確認済] にせず、主要な項目はすべて公式ページを直接開いて照合しました。照合した公式ページは、Claude Code changelog、Code Mode ドキュメント、Platform リリースノート、Cowork/Desktop changelog、support.claude.com の各記事、anthropic.com、status.claude.com です。

A. Claude Code（重点）

A-1. v2.1.323：Code Mode（実験的・オプトイン）

[確認済]（Claude 側の「ドキュメントは 404」は [棄却]）

  • Claude が JavaScript を書いて、複数のツール呼び出しを1回でまとめて実行する機能です。既定はオフで、CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 で有効になります。
  • 使えるのは、ネイティブビルドの対話型ターミナルだけです。-p、SDK、VS Code、Desktop、クラウドでは動きません。
  • 使えないアカウント構成があります（ゲートウェイ、Bedrock、Vertex 系、HIPAA、ZDR）。
  • 組織で禁止するには、managed settings で値を 0 にします。
  • ドキュメントは実在し、codex の記述と一致しました。
  • ドキュメントにトークン削減率などの数値はありません。Claude 側が挙げた「37%削減」は一次情報で確認できませんでした。
  • 出典: https://code.claude.com/docs/en/code-mode ／ https://code.claude.com/docs/en/changelog

A-2. v2.1.325：sandbox 内の Bash が通常の許可フローに従う（既定の変更）

[確認済]

  • sandbox 内の Bash も確認を求めるようになりました。以前の動作に戻すには sandbox.autoAllowBashIfSandboxed: true を設定します。managed settings では、最上位のソースに書く必要があります。
  • Claude 側だけが報告していましたが、changelog 原文と Desktop changelog の両方で確認しました。
  • 出典: https://code.claude.com/docs/en/changelog ／ https://claude.com/docs/cowork/changelog

今日の注目

  1. v2.1.325 の sandbox Bash 確認化と、無人実行への影響（A-2・A-3）
  • cron や /loop の定期実行は、sandbox 内の Bash と allowed-tools 付きの skill の両方で、確認待ちのまま止まる可能性があります。
  • 原文には、無人実行に関わる変更がほかにもあります（どちらの AI も触れていません）。
  • Desktop / IDE / SDK の「Always allow」の変更により、スケジュールタスクが確認待ちになる場合がある
  • メールアドレス確認の対象が、スクリプト・ファイル書き込み・web fetch・MCP 呼び出しにも広がった
  • autoAllowBashIfSandboxed と Skill(name) の要否を、自分の環境で一度にまとめて確認する価値があります。
  1. desktopHome の知見の更新（B-2）
  • Code だけの構成では、新版の Desktop は 12/17 まで切り替わりを延期しています。
  1. Code Mode（v2.1.323）の試用（A-1）
  • ドキュメントで次のことが確定しました。
  • auto mode の分類器は、ツール呼び出し単位ではなくコード単位で判定する
  • PreToolUse で REPL にマッチさせれば、コード本体を検査できる
  • PreToolUse hook がタイムアウトすると、ツール呼び出しは拒否される
  • 既存の hooks や deny 床の設計に影響する可能性があります。対話ターミナルだけの機能で、-p では動かないため、定期パイプラインには直接影響しません。
  • まず手元で、hooks の挙動とトークン量を実測してください。
