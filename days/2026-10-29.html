A. Claude Code（v2.1.307〜312）

A-1. v2.1.312：prompt/agent hooks の同時実行数に上限

[確認済] prompt/agent hooks は、サブエージェントを含めてセッションあたり最大24件まで同時に実行されます。これとは別枠で、イベントの timeout を過ぎても待っているものが最大12件です。1秒未満の timeout は1秒として扱われます。2系統が一致しており、changelog 原文でも確認しました。
出典: https://code.claude.com/docs/en/changelog

A-2. v2.1.312：サブエージェントの autoCompactWindow が効くようになった

[確認済] これまでは効果がありませんでしたが、v2.1.312 から CLAUDE_CODE_AUTO_COMPACT_WINDOW の値を下げる方向にだけ働きます（上げることはできません）。2系統一致、changelog 原文で確認しました。
出典: 同上

A-3. v2.1.312：Claude Code が認識しないモデル名には短いシステムプロンプトを使う

[確認済] 対象は Bedrock / Vertex / Foundry / Mantle です。カスタムデプロイ名や inference profile ARN のように Claude Code が認識しないモデル名では、中身が Sonnet や Haiku でも短いシステムプロンプトになります。従来のフルプロンプトを使い続けるには CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0 を設定します。codex だけが挙げた項目ですが、changelog 原文で確認しました。
出典: 同上

A-4. v2.1.312：cd 後に paths: スキルが見つからない不具合と、不正なコマンド名で claude -p が無出力になる不具合を修正

[確認済]

  • Bash で cd して深い階層に移ると、ディレクトリ単位や paths: 指定のスキルが見つからなくなる不具合を修正しました。
  • 名前が不正なコマンドが1つあるだけで全コマンドの読み込みが止まり、claude -p が何も出力しなくなる不具合を修正しました。
  • 前者は2系統一致、後者は codex のみですが、どちらも原文で確認しました。

出典: 同上

A-5. v2.1.312：巨大な CLAUDE.md や rules ファイルを冒頭しか見ずに上書きする不具合を修正

[確認済] 対象はサブディレクトリにある巨大な CLAUDE.md、rules ファイル、@ で取り込んだファイルです。今後は Write ツールが「全体を読むか、部分編集するか」を Claude に促します。Claude 側だけが挙げた項目ですが、原文で確認しました。
出典: 同上

出典: 同上

A-7. v2.1.311：ultrathink でそのターンが xhigh effort になる

[確認済]

  • 条件は、インタラクティブなターミナルで、Anthropic API 経由の Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1 を使っていることです。

  • Classmethod の記事は「公式ドキュメントは古い記述のまま」と指摘していましたが、今日（10/29）の時点ではドキュメントは更新済みです。記事が書かれた10/27時点の記述は確認できません。

出典: 同上 / https://code.claude.com/docs/en/model-config

A-10. v2.1.311：CLAUDE.md の長いリスト項目によるフリーズと、コンパクション直後に古い CLAUDE.md / MEMORY.md が見える不具合を修正

[確認済] 2系統一致、原文で確認しました。Qiita の個人検証（Windows・Sonnet 5.5・各条件3回）も、v2.1.310 では編集前の内容、v2.1.311 では編集後の内容が戻ることを観測しています。ただし v2.1.310 でも、要約に新しいルールが残っていたため、Claude の動作は新ルールに従っていました。この実測は1つの記事だけで、一般化はできません。

A-11. v2.1.311：サブエージェントと MCP、worktree、コンパクション、/usage 周りの修正

[確認済] 2系統のどちらかが挙げたもので、すべて原文で確認しました。

  • サブエージェントの起動後に接続を終えた MCP サーバーのツールを、そのサブエージェントが使えなかった。
  • バックグラウンドの子エージェントがまだ作業している worktree が削除されていた。
  • 標準コンテキストのセッションで 200K を超えると「Usage credits required for 1M context」で停止していた。今はコンパクションして続行する。
  • 要約が返ってこなかった場合、会話を置き換える前に要約を1回だけ再度依頼するようになった。
  • 数千行を変更する Write / Edit が最大5秒止まっていた。
  • /usage に大きなプロンプトキャッシュミスが表示されていなかった。
  • Pro / Max で、前回のチェックから1時間以内の起動ではネットワーク要求を2つ省くようになった。改善率の数値は公式に出ていません。

出典: 同上

  • codex だけが挙げた項目ですが、原文で確認しました。

A-14. v2.1.309：サンドボックス強化ほか

[確認済] Claude 側だけが挙げた項目ですが、すべて原文で確認しました。

  • サンドボックス内の Bash を実行する前に、シェルの起動ファイルがサンドボックスの外で実行されていた問題を修正しました。
  • サンドボックス内のコマンドが --mcp-config で渡した設定ファイルを書き換えられた問題を修正しました。
  • 上限サイズを超えるネストした CLAUDE.md は、冒頭だけ読み込むようになりました。

今日の注目

  1. v2.1.312 で直った「不正なコマンド名1つで claude -p が無出力になる」不具合（A-4）

cron で claude -p を使っている今回の収集・検証パイプラインに直撃する不具合です。出力が空でも「何も起きなかった」と区別がつきにくいのが厄介です。次の3点を確認する価値があります。

  • バージョンを v2.1.312 以上に上げる。
  • .claude/commands 配下に名前の不正なコマンドがないか確認する。
  1. v2.1.312 の hooks 同時実行上限（24 / 12）と、サブエージェントの autoCompactWindow が効くようになった件（A-1 / A-2）
  1. Cowork v4.29.0 のスケジュールタスクの web fetch 制限と、悪意ある CLAUDE.md で ANTHROPIC_BASE_URL を書き換えさせる手口（B-2 / F-1）
  • Cowork のスケジュールタスクで、指示文に書いていない URL を fetch している処理は、Auto モードと Skip all approvals モード以外では動かなくなります。
  • あわせて、.claude/settings.json に見覚えのない ANTHROPIC_BASE_URL がないかを検査する仕組みを入れる価値があります。deny の下限設定や hook で書き込みを止められるかも確認してください。
