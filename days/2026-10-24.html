1. Claude Code(最重要)

1-1. 2.1.309: サイズ上限を超えた入れ子の CLAUDE.md は先頭部分だけ読み込む

[確認済] 巨大な入れ子の CLAUDE.md があると、配下のファイルを読んだ後に圧縮が繰り返される不具合の修正です。上限を超えた入れ子の CLAUDE.md は、先頭部分だけ読み込まれるようになりました。codex 単独の主張ですが、changelog の原文で確認しました。「重要なルールを末尾に置かない」は codex 自身の運用上の判断で、仕様ではありません。
出典: https://code.claude.com/docs/en/changelog

1-2. 2.1.309: sandbox・権限継承まわりのセキュリティ修正

[確認済] 原文で次の3点を確認しました。

  • sandbox 内の Bash が、シェルの起動ファイルを sandbox の外で実行していた問題の修正
  • --mcp-config で渡した MCP 設定ファイルを、sandbox 内のコマンドや自動承認された編集が書き換えられた問題の修正
  • 分割ペインの teammate が、リーダーの deny や --tools 制限を継承していなかった問題の修正

いずれも codex 単独の主張でした。
出典: 同上

1-3. 2.1.309: claude ultrareview に workspace trust が必須になった、ほか

[確認済]

  • ultrareview は端末なら trust を確認し、それ以外では拒否します。スクリプトからは --trust-workspace(値を取らない)を付けるか、CLAUDE_CODE_DISABLE_ULTRAREVIEW_TRUST_CHECK=1 を設定します。
  • bypass モードで危険な rm/rmdir を即座に拒否する変更は、Desktop と VS Code に限った話です。Claude の出力はこの条件を省いています。
  • sed -i は通常の Bash 確認を経て実行されるようになり、/rewind でも戻らなくなりました。
  • --add-dir 配下の skill 名の衝突は <folder>:<name> で解決されます。入れ子パッケージで /verify・/code-review が専用 skill を見つけられない問題も修正されました。

出典: 同上

1-4. 2.1.307: /claude-api api-version と OTel claude_code.safety_event

[確認済] 両 AI が一致し、原文でも確認しました。

  • /claude-api api-version は、コードを API 2026-10-21 に移行するコマンドです。
  • safety_event は、権限ルール・auto mode・安全チェック・hook・sandbox がツール呼び出しを止めたり、確認を求めたり、差し戻したりしたときに記録されます。
  • 同じ版で @claude review stop(off/pause も可)が追加されました。
  • 同じ版の修正: cloud 再起動後に /autocompact 設定が既定に戻る問題、/clear した会話が復活する問題、サブエージェントのトランスクリプトのトークン使用量が仮の値になる問題。

API 版の内容そのものは既存の知見と整合しています。
出典: 同上

1-7. 2.1.305: sandbox.allowNestedUserNamespaces / CLAUDE_CODE_RETRY_WATCHDOG_USAGE_LIMIT_RECHECK_MS

[確認済] Claude 単独の主張ですが、原文で確認しました。

1-8. 2.1.304: 再開時の5時間枠警告 / /auto-mode-setup / --max-turns / Cowork の URL 承認待ち

[確認済] 原文で次を確認しました。

  • 非アクティブな会話を再開すると Pro/Max の5時間枠を大きく使う場合に、警告が出るようになりました。
  • /auto-mode-setup がガイド付きで追加されました。Bedrock・Vertex・Foundry・apps gateway・telemetry 無効のセッションでも使えます。
  • plugin がサブエージェントを起動して、--max-turns や Stop の後も headless 実行を続けてしまう問題が修正されました。
  • Cowork の予約 cloud セッションで、URL 承認待ちの5分がサブエージェントごとに繰り返される問題が修正されました。

出典: 同上

1-9. 2.1.304: 圧縮後に skill 一覧を再送 / /reload-skills は差分のみ / skill hooks の上限

[確認済] Claude の主張と原文が一致しました。skill hooks の上限は、ソースごとに 1,024 個、matcher は 16,384 文字までです。カスタム ANTHROPIC_BASE_URL でも tool search が既定で有効になり、400/422 が返った場合は tool search なしで再試行します。Code Review に Quick/Standard/Deep のレベルが加わったことも確認しました。ただし Claude が書いた「組織の全リポジトリをレビューする設定」は、一次確認できていません。

2. Cowork / Desktop

2-1. 10/23 Enterprise で Chat と Cowork を統合(GA)

[確認済] 両 AI が一致し、公式記事でも確認しました。内容は次のとおりです。

  • コードやファイルが必要になると、作業が cloud 環境に移ります。
  • 既存のチャット・プロジェクト・コネクタ・skills・plugins は引き継がれます。
  • Efficient mode は Sonnet/Haiku に限定する管理設定です。
  • 予算は組織・グループ・メンバーの3段階で設定でき、グループで共有する月額予算も使えます。
  • cloud セッションは1つずつ隔離された VM で動き、外向き通信は既定でオフです。
  • ZDR・HIPAA・CMEK を使う組織は現行構成のままです。

codex の「PC を閉じても継続」は、私の取得結果には明記がありませんでした。
