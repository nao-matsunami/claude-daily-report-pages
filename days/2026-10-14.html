A. Claude Code(重視)

A-1. v2.1.295: command/HTTP hook に onFailure: "block" を追加

[確認済](2系統が一致し、changelog と hooks ドキュメントでも確認)

  • hook が起動できない、タイムアウトする、終了コードが0か2以外、HTTP エラー、出力 JSON が不正、のいずれかで操作をブロックします。既定値は continue です。
  • 効かないケースがあります。Stop/SubagentStop/TaskCompleted/TeammateIdle と、async/asyncRewake の hook では無効です(codex の主張どおり)。
  • 既定のまま(continue)なら失敗時は素通りなので、hook の timeout は fail-open という既存知見と矛盾しません。
  • 出典: https://code.claude.com/docs/en/hooks , https://code.claude.com/docs/en/changelog

A-2. v2.1.294: 指示文で書いた prompt/agent hook が、ブロックすべきものを通してしまう問題を修正

[確認済](2系統が一致し、changelog で確認)

  • 「Block commands that...」のような書き方の hook が止めずに通してしまう不具合が修正されました。
  • Stop/SubagentStop の prompt hook は「改善」扱いで、Claude が早めに作業をやめにくくなりました。不具合修正ではありません。
  • 出典: changelog

A-3. v2.1.295: サブエージェント・skills・SessionStart まわりの修正

[確認済](2系統が一致し、changelog で確認)

  • skills で事前ロードするスキルは最大32個、各1回までになりました。
  • Workflow サブエージェントから呼んだ fork スキルの結果が、呼び出し元ではなくメイン会話に届いていた不具合が修正されました。両者の書き方は逆に見えますが、codex は不具合を、Claude は修正後の挙動を書いているだけで、内容は同じです。
  • 非同期 SessionStart hook の同じ文脈が、resume のたびに重複して追加される問題が修正されました。
  • 出典: changelog

A-4. v2.1.295: headless/長時間実行の安定化

[確認済](codex が主張し、changelog で確認)

  • headless/SDK セッションで、リモート MCP が15秒以上切れると復帰しない問題と、再接続が詰まったループになる問題を修正しました。今は最大30秒の backoff で再接続します。
  • claude -p で、バックグラウンド作業が別ターンを始めたときに前の応答が出力から抜ける問題を修正しました。
  • gateway/Bedrock/Vertex/Foundry が context-1m beta を拒否したとき、[1m] モデルの全リクエストが失敗していた問題を修正しました。今は beta ヘッダーを外して再送します。
  • 出典: changelog

A-5. v2.1.296: サブエージェント用 autoCompactWindow と CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL

[確認済](2系統が一致し、changelog で確認)

  • サブエージェントの frontmatter と --agents 定義で、メイン会話より早く自動コンパクトさせられるようになりました。
  • 環境変数を使うと、Workflow エージェントだけを1つのモデルに固定できます。他のサブエージェントの設定はそのままです。
  • 出典: changelog

A-6. v2.1.296: Read の allow_large、非UTF-8ファイル編集の拒否、MCP 説明文の上限拡大、managed PreToolUse の修正

[確認済](2系統が一致し、changelog で確認)

今日の注目

  1. onFailure: "block"(v2.1.295)を deny 床の hook に入れる
  • 理由: hook の timeout が fail-open だった穴を、設定だけで塞げます。
  • 注意: Stop/SubagentStop と async hook には効きません。PreToolUse 系の安全 hook に絞って入れ、スクリプトを欠落させたときにブロックされるか実機で確認する価値があります。
  1. v2.1.295 の headless 修正と MCP protocol 既定の変更が、cron 実行に与える影響の棚卸し
  • 理由: 次の3つの修正は、定期実行のブリーフ収集に直接関係します。
  • claude -p で前の応答が出力から抜ける問題
  • headless でリモート MCP が復帰しない問題
  • 非同期 SessionStart の文脈が resume のたびに重複する問題
  • 逆に MCP protocol 2026-07-28 が既定になったので、古い MCP サーバーが壊れる可能性もあります。更新後の出力が欠けていないか、MCP がつながるかを確認し、壊れたら MCP_PROTOCOL_NEGOTIATION=legacy を試すのが妥当です。
  1. スタンドアロン版 Claude Design の終了(12/14)と、Enterprise での既定有効化(10/15、明日)
  • 理由: プロジェクト、チャット、コメントは移行されず、終了後に削除されます。必要なプロジェクトは早めに ZIP で書き出す必要があります。
  • Enterprise 組織では、明日から Design・Docs・Slides が既定で有効になります。管理者設定を事前に確認しておく必要があります。
