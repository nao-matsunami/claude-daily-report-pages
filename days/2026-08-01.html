B. Claude Code（重点）

8. v2.1.219（2026-07-24）— 今週の実質的な中身はここに集中

[確認済] 公式 changelog で全項目確認。codex / Claude の記載はほぼ正確。

  • Opus 5 がデフォルトの Opus モデルに（1M context、fast mode は $10/$50 per Mtok）
  • sandbox.network.strictAllowlist：許可リスト外ホストをプロンプトなしで拒否
  • DirectoryAdded フック（/add-dir / SDK register_repo_root 後に発火）
  • サブエージェントのネスト生成が既定 depth 3 に（従来1。CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 で無効化）
  • workflowSizeGuideline 設定キー追加 / 動的ワークフローの既定サイズが medium（15エージェント未満目安）
  • stream-json：mcp_server_errors を init イベントに追加、ネストサブエージェント転送
  • fast mode から Opus 4.7 を除外（/fast は Opus 5 / 4.8 対象）
  • claude-api skill の既定を Opus 5 に変更

→ https://code.claude.com/docs/en/changelog

今日の注目（検証・実装を試す価値のある更新）

1. MCP 2026-07-28 のステートレス化 — 最優先
initialize ハンドシェイクと Mcp-Session-Id を前提にした自作 MCP サーバーは、request/response モデルへの移行で挙動が変わる可能性があります。Claude Code / Cowork 双方に効くうえ、MCP Apps（会話内UI描画）と Tasks（長時間処理）は今すぐ試せる新しい設計余地です。今週唯一の「仕様レベル」の変更で、影響範囲が最も広い。

2. Claude Code のネストサブエージェント depth 3 + workflowSizeGuideline
既定値の変更なので、アップデートしただけで自分のエージェント構成の挙動が変わっています。多段委譲を組んでいるなら実挙動の確認を推奨。逆に想定外のネストを避けたいなら CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1 で明示的に戻せます。sandbox.network.strictAllowlist も、サンドボックス実行の許可プロンプトを減らせる実用的な追加です。
