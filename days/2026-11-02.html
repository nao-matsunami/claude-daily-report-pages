Claude/Anthropic 直近の動き 精査結果(対象: 2026-10-26〜11-02)

確認方法: 一次情報として次のページを直接読みました。code.claude.com changelog、platform.claude.com release notes、claude.com/docs/cowork/changelog、support.claude.com release notes、anthropic.com news 2本、claude.com articles 1本、arXiv 1本。HN の2スレッドも読みました。それ以外のURLは開いていないため、その項目には「未照合」と書いています。11/1〜11/2 の公式エントリは、どのページにもありませんでした。

A. Claude Code(重点)

A-1. v2.1.316(10/31):CLAUDE_CODE_SUBAGENT_EFFORT 追加
[確認済] 2系統が一致し、changelog 原文でも確認しました。ほかに指定がない場合、サブエージェントは親セッションの effort を引き継がず、この値で動きます。

A-2. v2.1.316:CLAUDE_CODE_DISABLE_ULTRATHINK 追加
[確認済] changelog 原文に「turns the ultrathink keyword off」とあります。Claude 側は「changelog で確認できず」と書いていましたが、実際には記載がありました。

A-3. v2.1.316:hooks・子エージェント・終了処理の修正
[確認済] 次の3点が原文と一致しました。

  • 型キャスト・param・using・属性で始まる PowerShell hook が、終了コード2でもブロックしなかった問題の修正
  • 自分で終了したとき(認証拒否やクラウドセッションのアーカイブなど)に、macOS/Linux のシェルコマンドが残る問題の修正
  • 親サブエージェントのモデルを継承した子が、バックグラウンドジョブやメッセージで起こされたときにメインのモデルへ戻る問題の修正

正確には「再開時」ではなく「起こされたとき」です。/diff の軽量化も原文で確認しました。

A-4. v2.1.314(10/30):PreCompact hook の出力を hook ごとに 10,000 文字で切り詰め
[確認済] 2系統が一致し、原文でも確認しました。出力が巨大なときに compaction が失敗したり繰り返したりする問題への対処です。

A-5. v2.1.314:アイドル時コンパクションを VS Code / Desktop の Code タブに拡大
[確認済] 原文と一致しました。対象は 200K トークン以上で放置された会話です。prompt cache が切れていた場合、次のメッセージで要約が使われます。

A-6. v2.1.314:メモリ・--resume・skills 監視・/context の改善
[確認済] 次の4点が原文と一致しました。

  • サブエージェントを多数使う headless / SDK の長いターンで、親が各子のツール結果をターン終了まで持たなくなった
  • 破損した transcript での --resume が速くなり、メモリ使用も減った
  • ~/.claude/skills/.trash を監視しなくなった
  • MCP ツールが1万件以上あるときの /context が速くなった

A-7. v2.1.314:hook の if 条件が Monitor ツールのシェルコマンドにもマッチ
[確認済] 原文で確認しました(Claude 側のみが報告)。Monitor が起動したコマンドに対して Bash 用 hook は block / ask はできますが、approve や書き換えはできません。

A-8. v2.1.314:permissions.blockWritesOutsideWorkingDirectories 追加
[確認済] Claude 側は二次情報扱いでしたが、changelog 原文の Added にありました。どの権限モードでも、Write / Edit / NotebookEdit が作業ディレクトリ外のパスを拒否します。

A-9. v2.1.312(10/27):hook の並列数制限と、サブエージェントの autoCompactWindow
[確認済] 2系統が一致し、原文でも確認しました。

  • prompt / agent hooks は、サブエージェントを含めて1セッションあたり同時24件まで。これとは別に、timeout を超えて待っているものが12件まで。1秒未満の timeout は1秒として扱われます。
  • サブエージェントの autoCompactWindow は、CLAUDE_CODE_AUTO_COMPACT_WINDOW の値を下げられるようになりました。上げることはできません。

A-10. v2.1.312:CLAUDE.md・skills・コマンドの修正
[確認済] 2系統が一致し、原文でも確認しました。

  • サブディレクトリの巨大な CLAUDE.md / rules / @-include ファイルを、冒頭だけ見て上書きする問題の修正
  • cd で深い階層に入った後、ディレクトリ単位や paths: 指定の skills が見つからない問題の修正
  • 名前が不正なコマンドが1つあると全コマンドが読み込まれず、claude -p が何も出力しないことがある問題の修正

A-11. v2.1.311(10/26):起動・CLAUDE.md・compaction 関連の修正
[確認済] Claude 側のみが報告しましたが、すべて原文で確認しました。

  • Pro/Max で、前回チェックから1時間以内の起動はネットワークリクエストを2回省略
  • 長いリスト項目を含む CLAUDE.md でのフリーズを修正
  • 自動コンパクト直後に、編集済みの MEMORY.md / CLAUDE.md の古い内容が見える問題を修正
  • 200K 超で「Usage credits required for 1M context」により止まる問題を修正(コンパクトして続行するようになった)
  • SubagentStop が約1分に2回発火していた問題を修正
  • DISABLE_COMPACT は設定ファイルからはオフにしかできなくなった

A-12. 2.1.313 は欠番
[確認済] changelog に 2.1.313 はありません。HN の Anthropic スタッフも「公式チャネルでは公開していない。混乱を避けるため次は 2.1.314 にした」と述べており、内容が合います(C-1 を参照)。

A-13. サブエージェントの effort を分けた実測(Classmethod、10/31)
[要検証] 報告は Claude 側だけで、記事は開いていません。変数そのものは A-1 で確認済みです。「環境変数なしだと子も high、=low を付けると子だけ low になる」という実測結果は、原文を読んでいません。

A-14. バックグラウンドエージェントの状態ラベル生成によるトークン消費(HN)
[要検証] HN スレッドは実在しました(585pt)。

  • 「約30秒ごとに、各バックグラウンドエージェントの transcript を cache 付きの fork としてモデルに送る」というのは、gist とコメント欄による解析です。公式の説明ではありません。
  • 消費割合は個人の自己申告で、16% / 最大8% / 約3% とばらつきがあります。
  • 私が読んだ範囲には「Anthropic が修正を出した」という発言はありませんでした。ただしスレッドの後半(約2割)は読んでいないので、修正が無いことを確認したわけではありません。
  • 対策として挙がっていた「idleCompaction をオフにする」が効くかどうかも確認できていません。

A-15. compaction 調整のコツ(aicoding-guide)
[要検証] 報告は Claude 側だけで、記事は開いていません。CLAUDE_CODE_AUTOCOMPACT_PCT_OVERRIDE や /autocompact 500k などの設定名・コマンド名は、一次情報で確認していません。

B. Cowork / Desktop(重点)

B-1. クラウドの Cowork セッションの auto mode で、MCP 呼び出しへの hook の allow を「無回答」扱いに変更(CC v2.1.314)
[確認済] codex 側のみが報告しましたが、changelog 原文で確認しました。hook の allow だけでは許可されず、分類器か権限確認が判断します。

B-2. Desktop v4.29.0(10/27)
[確認済] Claude 側のみが報告しましたが、原文で確認しました。

  • 「Skip all approvals」は、Claude Code の設定ではなく組織の Cowork 設定に従うようになった
  • スケジュールタスクの web fetch は、Auto / Skip all approvals 以外のモードでは、指示に書かれたURLか、検索・前回の取得で見つかったURLに限定
  • Windows でフォルダを削除すると、ジャンクションやマウント経由で外のファイルまで消える問題を修正

B-3. Desktop v4.4212.0(10/29)
[確認済] 原文と一致しました。内蔵ブラウザにサイトごとの「Local network access」設定が加わり、Claude Doc の Share メニューに Canva などへの「Send to」が加わりました。同梱されている Claude Code は 2.1.309 です。

B-4. (収集外。検証中に見つけたもの)11/10 から未設定の desktopHome の既定が変わる
[確認済] v4.29.0 と v4.4212.0 の 3P セクションに breaking として書かれています。11/10 12:00 PT 以降の起動では、desktopHome が未設定だと Unified Claude が Cowork オンの状態で開きます(coworkTabEnabled: false でも同じ)。サードパーティ展開を使っている場合は対象です。

B-5. 9/16 に Cowork がチャットへ統合、10/6 から新規タスクはクラウド実行(期間外の背景)
[要検証] 一次・二次とも開いていません。support のリリースノートに 9/16 の Cowork エントリがあることだけは確認しましたが、中身は読んでいません。
