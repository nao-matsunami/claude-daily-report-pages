Claude / Anthropic 直近の動き 突き合わせ結果（2026-11-08〜11-14）

一次情報は WebFetch で以下を確認しました: code.claude.com の changelog と Code Mode ページ、platform のリリースノート、Cowork changelog、support のリリースノート、anthropic.com/news、claude.com の各記事。changelog は分量が多く、冒頭約10万字（2.1.321〜2.1.325）だけを読んでいます。

A. Claude Code

A-1. v2.1.321（11/09）: Fable 5.2 が Fable の既定モデルに

[確認済] 2系統が一致し、changelog の原文とも合っています。原文は「claude-fable-5-2, now the default Fable model — 1M context, $8/$40 per Mtok with $0.20/Mtok cache reads」です。これは「Fable 系の中での既定」であり、Claude Code 全体の既定モデルが変わったわけではありません。
出典: https://code.claude.com/docs/en/changelog

A-2. v2.1.321 のその他の変更

[確認済] Claude 側だけが挙げた項目ですが、すべて原文で確認しました。

  • claude remote-control --settings <file> の追加
  • 1,000字を超えるバックグラウンドコマンドの通知と TaskStop の結果を、先頭と末尾だけ表示
  • Cowork クラウドセッションで、PostToolUse hook が AskUserQuestion / ExitPlanMode の結果を置き換えられなくなった
  • ~/.claude/plugins 内の .claude/skills を読み込まなくなった
  • ツール定義の過大計上を修正（codex 側の記載）

A-3. v2.1.322（11/10）: Vertex で fast mode に対応

[確認済] 2系統が一致し、原文とも合っています。global / us / eu リージョンが対象で、Vertex が拒否した場合は通常速度に戻ります。

A-4. v2.1.323（11/12）: Code Mode（実験的・opt-in）

[確認済] 公式ページは現在存在します。要件は次のとおりです。

  • v2.1.323 以降、native build、ターミナルでの対話セッション
  • -p、Agent SDK、VS Code パネル、Desktop、クラウドセッションでは動きません
  • gateway、Bedrock、Foundry などは不可。HIPAA 構成と ZDR の組織も不可
  • 対応モデルは Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.2
  • CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 で有効化します。プロジェクト設定からは有効化できず、managed settings で 0 にすると組織全体で禁止できます
  • auto mode の classifier はツール呼び出しごとではなく、コード単位で審査します

Claude 側は「ドキュメントは11/13時点で404（二次）」としていました。11/13時点の状態は確認できませんが、少なくとも現時点で「仕様が確認できない」という状況は解消しています。
出典: https://code.claude.com/docs/en/code-mode

A-5. v2.1.323: 認識できないモデルIDの想定コンテキストを 200K から 1M に変更

[確認済] Claude 側だけの記載ですが、原文で確認しました。/autocompact を使うか、CLAUDE_CODE_DISABLE_1M_CONTEXT=1 で 200K のままにできます。既存の知見が「未知のIDは 200K」を前提にしていれば、ここは更新が必要です。

A-6. v2.1.323: hooks と権限の変更

[確認済] 原文で確認しました。

  • PreToolUse が allow を返した後に権限チェックがエラーになった場合、hook が応答しなかったものとして扱う
  • PermissionRequest hook が書き換えた入力でチェックが失敗した場合、再確認する（答える人がいなければ拒否）
  • -p / SDK で hook が長く走るとき、30秒ごとにハートビートを送る
  • 秘密情報らしき文字列を含むルールや、git 管理下の settings.local.json に保存されるルールは、「don't ask again」でもセッション限り
  • Bash(PORT= …) のように変数の値に を含むルールに起動時の警告
  • /security-review は実行前に確認を求めるようになった

A-7. v2.1.323: サブエージェント、圧縮、plugin

[確認済] 2系統の記載を合わせて、原文で確認しました。

  • 終了したサブエージェントの transcript を早めに解放
  • サブエージェントの圧縮時、PreCompact / PostCompact / SessionStart に agent_id と agent_type が渡らない問題を修正
  • /compact を再実行すると未回答のメッセージが要約で消える問題を修正
  • safeguard で止まった後の指示を「範囲を絞って再試行するか、ユーザーに伝える」に変更
  • CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES を追加（2.1.318 から使用可能だったと明記）
  • subagentStatusLine 設定を廃止（キーが残っていても読み込みは従来どおり）
  • plugin.json に engines["claude-code"] を追加
  • claude plugin validate が TypeScript hooks を型チェック（--strict で失敗扱い）
  • plugin の agent 設定を非推奨化

A-8. v2.1.325（11/13）: scheduled tasks と /loop が skill 実行前に確認を求める

[確認済] Claude 側だけの記載ですが、原文で確認しました。対象は allowed-tools か hooks を宣言している skill です。無人で実行するには permissions.allow に Skill(name) を追加します。

Claude 側は対象に「-p」も含めていましたが、原文に書かれているのは scheduled tasks と /loop だけです。-p が対象かどうかは原文からは確認できません。

A-9. v2.1.325: sandbox 内の Bash が通常の権限フローに従う既定に

[確認済] Claude 側だけの記載ですが、原文で確認しました。従来どおりにするには sandbox.autoAllowBashIfSandboxed: true を設定します。managed settings で sandbox を有効にしている場合は、最上位の managed ソースに設定します。

A-10. v2.1.325: サブエージェントのモデルとコンテキストの修正

[確認済] 2系統の記載を合わせて、原文で確認しました。

  • 独自モデルのサブエージェントが、opusplan / haiku の設定時に plan 用モデルへ移される問題を修正
  • 別モデルのサブエージェントが、メインセッションのモデルを基準にファイル読み込みと MCP 結果の量を決めていた問題を修正
  • 多くの gateway / Foundry で、圧縮せずに毎ターン context length エラーになる問題を修正
  • bare リポジトリの worktree などで /security-review と skill 内の git コマンドが止まる問題を修正
  • zstd 復号のセキュリティ修正
  • CLAUDE_CODE_MAX_CONTEXT_TOKENS が claude- で始まる未知IDにも効くように変更
  • 出力上限で途切れたサブエージェントに、短くした全体の回答を再要求するよう改善
