A. Claude Code（重点）

A-1. v2.1.317（11/3）Agent SDK フックに onFailure: "block" を追加

[確認済]（両AIが一致し、changelog 原文でも確認）
フックのコールバック自体が失敗したとき、操作を通さずに止められるようになりました。
出典: https://code.claude.com/docs/en/changelog

A-2. v2.1.317 Read ツールの「前回から変更なし」表示を廃止

[確認済]（Claude のみ。changelog 原文で確認）
変更のないファイルを読み直しても中身が返るようになりました。トークン消費がどれだけ増えるかは確認できていません。
出典: 同上

A-3. v2.1.317 別モデルで動くサブエージェントの effort が変更

[確認済]（Claude のみ。原文で確認）
メイン会話と別モデルのサブエージェントやチームメイトは、セッションの effort を使わなくなりました。代わりにそのモデルで保存された effort（なければ既定値）を使います。
出典: 同上

A-4. v2.1.317 その他の修正

[確認済]（原文で確認）

  • headless でコマンド登録型プラグインが多いと、メモリ使用が増えて起動が遅くなる問題を修正
  • claude.ai から同期した skills が消えたり、10分ごとに再ダウンロードされたりする問題を修正
  • Desktop の Code タブなど、先に起動しておいたセッションでプロジェクトの effortLevel が無視される問題を修正
  • /schedule の結果から、次回実行時刻とリンクが抜ける問題を修正
  • 実行中のバックグラウンドエージェントへの SendMessage が早く届くように変更
  • 再開したセッションで、既知のファイル変更を再通知する問題を修正

前の4件は codex、後の2件は Claude が拾ったものです。
出典: 同上

A-5. v2.1.316（10/31）CLAUDE_CODE_SUBAGENT_EFFORT を追加

[確認済]（Claude のみ。原文で確認）
どこでも effort が指定されていないとき、サブエージェントが使う effort をこの変数で決められます。これまではセッションの effort を引き継いでいました。A-3 と同じく、agent-effort-param-subagent-fit.md の前提に関わります。
出典: 同上

A-6. v2.1.316 CLAUDE_CODE_DISABLE_ULTRATHINK を追加、PowerShell フックの終了コード2を修正

[確認済]（両AIが一致し、原文で確認）
PowerShell フックの修正には条件があります。対象は、コマンドが型キャスト・param・using・属性で始まる場合だけです。
出典: 同上

A-7. v2.1.316 サブエージェントのモデル継承と register_repo_root の修正、/model の警告追加

[確認済]（両AIが一致し、原文で確認）

  • 親サブエージェントのモデルを継承した子が、起こされたときにメインモデルへ戻る問題を修正
  • SDK の register_repo_root で、作業ディレクトリ外の CLAUDE.md が読まれない問題を修正（CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 を使う場合）
  • /model <id> で未知のモデルを指定したとき、auto-compact が 200K ウィンドウを前提にすることを警告するように修正

出典: 同上

A-8. v2.1.314（10/30）アイドル時コンパクションの対象拡大

[確認済]
VS Code とデスクトップの Code タブでも動くようになりました。Bedrock / Vertex / Foundry / LLM ゲートウェイでも、1時間のプロンプトキャッシュを有効にしていれば動きます。さらに原文には、テレメトリを切った契約者でも動くと書かれています。
出典: 同上

A-9. v2.1.314 permissions.blockWritesOutsideWorkingDirectories を追加

[確認済]
どの権限モードでも、Write / Edit / NotebookEdit で作業ディレクトリ外へ書き込めなくなります。
出典: 同上

A-10. v2.1.314 メモリ・速度・コンパクション関連の修正

[確認済]（両AIが一致し、原文で確認）

  • headless や SDK で多数のサブエージェントを回す長いターンでも、親が各ツール結果をターン終了まで保持しなくなった
  • 破損した会話ログからの --resume が速くなり、メモリ使用も減った
  • MCP ツールが1万個以上ある環境で /context が速くなった
  • 画像の多い Bedrock セッションで「400 Input is too long」が出る問題を修正
  • PreCompact フックの出力を 10,000 文字で切るように変更
  • フックの if 条件（例: Monitor(tail *)）が、Monitor のシェルコマンドにもマッチするように変更
  • 巨大な CLAUDE.md が変わったセッションで、自動コンパクション後に「Prompt is too long」が出る問題を修正
  • 非常に長い会話で、以前の要約が消える問題を修正

最後の項目について、Claude は v2.1.317 の修正としていましたが、原文では v2.1.314 の修正です。「Prompt is too long」の修正は、既存知見 changelog-2-1-274 とは別の版の別の修正です。
出典: 同上

A-11. v2.1.312（10/27）

[確認済]（Claude のみ。原文で確認）

  • 巨大な CLAUDE.md や rules ファイルを、冒頭だけ見て Write で上書きしてしまう問題を修正
  • プロンプト型とエージェント型のフックは、同時に最大24個まで実行（タイムアウト超過で待っているものは別枠で最大12個、1秒未満の timeout は1秒扱い）
  • サブエージェントの autoCompactWindow で、ウィンドウを小さくできるように変更（大きくはできない）。

出典: 同上

今日の注目

  1. サブエージェントの effort 仕様変更（A-3 と A-5）
  1. Read ツールの「変更なし」表示の廃止（A-2）

長時間の cron セッションで同じファイルを何度も読む構成では、入力トークンが増える可能性があります。増え方は確認できていないので、/usage で前後を比べて実測する価値があります。

  1. 11/30 の期限: Opus 4.8 の fast mode 削除、Sonnet 4.5 の退役（C-2 と C-3）

削除後は自動フォールバックせずエラーになります。opus-4-1-retire-hardcode-scan と同じ要領で、claude-opus-4-8 と speed: "fast" の組み合わせや claude-sonnet-4-5 がリポジトリに残っていないか、期限前に洗い出すことを勧めます。

  • あわせて、PreCompact フックを使っているなら、出力が 10,000 文字以内に収まっているか確認しておくと安全です（A-10）。
