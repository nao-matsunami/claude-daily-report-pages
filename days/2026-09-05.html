前提

Gemini(agy)の出力は空でした。 今日は codex と Claude の2系統のみの突き合わせです。したがって「複数AIの一致」による確度付けは使えないため、私が今日 WebFetch で一次情報を直接取得した結果を確度の根拠にしています。以下、「[確認済]」は特記なき限り本日の一次取得で原文照合済みという意味です。

A. Claude Code changelog(最重要)

期間内は v2.1.252(8/31)〜 v2.1.261(9/4)。9/5 付エントリはなし。codex と Claude の版番号帰属は両者とも正確でした(2.1.260 と 2.1.261 の取り違えなし)。

A-1. /skill-doctor 追加(v2.1.261 / 9-4)

[確認済] 原文: "Added /skill-doctor to show which loaded skills go unused and what they cost in context, so you can prune them"。Claude 単独主張だが一次確認済み。
https://code.claude.com/docs/en/changelog

A-2. bashOutputMaxChars / taskOutputMaxChars(v2.1.261)

[確認済] インライン受け取り上限を 128K 文字まで引き上げ可能。超過分はファイル退避。Claude が「128Kトークン」的に書いていたが原文は characters。
https://code.claude.com/docs/en/changelog

A-3. --append-subagent-system-prompt-file(v2.1.261)

[確認済] サブエージェントのシステムプロンプトをファイルから読む。コマンドラインに載らない大きさ用。
https://code.claude.com/docs/en/changelog

A-4. /diff と /cost のキャッシュミス原因表示(v2.1.260 / 9-3)

[確認済] 両AI一致 + 原文一致。/cost と status line の prompt_cache に「ツール定義/システムプロンプト変更、TTL超過のアイドル」等の推定原因が出る。
https://code.claude.com/docs/en/changelog

A-5. プロンプトキャッシュ関連の修正が今週まとめて入った

[確認済] 原文で以下を個別確認:

  • Fable 5.1 でツール結果の後に付くコンテキストがキャッシュ対象外だった(v2.1.260)
  • /effort の途中変更が Fable 5.1 でキャッシュを壊さなくなった(v2.1.260)
  • エージェントチームのメンバーが2ターン目に初回ツール/スキル告知を再送してプレフィックスを変えていた(v2.1.261)
  • テレメトリ無効時の OAuth トークン更新でキャッシュ無効化(v2.1.259)
  • Stop hook のブロックでそのターンの推論が失われ、モデルによってはキャッシュも外れる(v2.1.259)
  • Remote Control 中途接続の Bash ツール定義再送 / advisor モデル設定時の背景リクエスト / スクショ多用セッション(v2.1.257)
  • /fork が元会話のキャッシュを引き継ぐ(v2.1.257)

https://code.claude.com/docs/en/changelog

A-6. 権限ルールのセキュリティ修正 — 括弧を含むパス(v2.1.260)

[確認済] 原文: "Fixed Edit/Write/Read permission rules whose path contains parentheses being dropped as invalid or ignored by the Bash sandbox, which left \"read-only\" folders writable"。加えてコンパイル不能パターン1件で全ファイル編集が Invalid regular expression になる不具合も同版で修正。
https://code.claude.com/docs/en/changelog
