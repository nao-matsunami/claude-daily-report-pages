統合ブリーフ 2026-08-30(対象期間 8/23–8/30)

A. Claude Code(最重視)

A-1. プロンプトキャッシュ関連の一括改善(v2.1.243 / v2.1.248 / v2.1.251)

[確認済] promptCacheTtl / subagentPromptCacheTtl 設定(2.1.243)、エージェント frontmatter の experimental.cacheTtl(2.1.248)、長時間セッションで約1時間ごとに発生していたキャッシュミスの修正(2.1.248)、/cost のセッション単位キャッシュ行とステータスライン用 prompt_cache オブジェクト(2.1.251)。changelog 原文で全項目を確認しました。
出典: https://code.claude.com/docs/en/changelog

訂正: Claude の出力は /cost キャッシュ行・PreModelSwitch・CLAUDE_CODE_SUBAGENT_MODEL 変更を v2.1.253 としていましたが、公式 changelog では v2.1.251 です。Claude 自身が注記していた「2.1.253 と 2.1.251 の食い違い」は、公式側が 2.1.251 で正しいという形で決着しました。

A-2. CLAUDE_CODE_SUBAGENT_MODEL の意味変更(破壊的)

[確認済] v2.1.251 で「全上書き」から「サブエージェントの既定モデル」に変更。エージェント定義の model: と spawn 時の明示指定が優先されます。既存の自動化で本変数に依存している場合は挙動が変わります。
出典: https://code.claude.com/docs/en/changelog

A-3. --restricted / CLAUDE_CODE_RESTRICTED=1(v2.1.248)

[確認済] コマンド/コード実行系の組込ツールと WebFetch を除去、ファイルツールを作業ディレクトリ内に限定、bypassPermissions を拒否、user/project/local の設定ファイルを無視。changelog 原文一致。
出典: https://code.claude.com/docs/en/changelog

A-4. --restricted で自作スキルが読まれなくなる(Qiita 実測)

[要検証] codex のみが引用する Qiita 記事(8/28、2.1.248 で「自作スキル47本が0本に」)。changelog の「user/project/local の設定ファイルを無視」とは方向性が整合しますが、Skills が読まれない点の一次記述は確認できていません。「誤りである」ことを確認したわけではなく、一次確認ができていない状態です。
出典: https://qiita.com/jqit_suwa/items/4183a8e97738ba45f435

A-5. PreModelSwitch / PostModelSwitch フック(v2.1.251)

[確認済] モデル切替をブロック・確認・注記できる新フックイベント。Claude 単独主張でしたが changelog で確認。
出典: https://code.claude.com/docs/en/changelog

A-6. ANTHROPIC_DEFAULT_MODEL

[確認済] v2.1.236 で追加。新規セッションの開始モデルを設定するが、/model での選択が上書きし再起動をまたいで永続する(ANTHROPIC_MODEL と異なる点)。codex 引用の Qiita「/model を一度押すと効かない」は公式記述と整合します。
出典: https://code.claude.com/docs/en/changelog

A-7. Remote Control の「Research Preview → GA 昇格」

出典: https://code.claude.com/docs/en/whats-new

[確認済] 実在を確認。481件の公開 CLAUDE.md を調査し、取得したセキュリティルールのうち組込コントロールに対応があったのは約4〜16%(最も厳しい推計で4.4%)。CLAUDE.md は「write-only チャネル」で、書いたルールが強制されるかのフィードバックが開発者に返らない、と指摘。結論は「守らせたい制約は permissions / sandbox / hooks に落とせ」。

今日の注目(検証・実装を試す価値がある更新)

1. /cost のプロンプトキャッシュ行で自環境のヒット率を実測する(v2.1.251)
理由: 「長時間セッションで約1時間ごとにキャッシュ全ミス」という不具合が v2.1.248 で修正されたばかりで、修正前後の差が測れるのは今だけです。加えて H-5 の「60〜80%が目安」という根拠不明の経験則を、自リポジトリの実測値で置き換えられます。ステータスライン用 prompt_cache オブジェクトも同時に来ているので、headless 定期実行のコスト監視に組み込めます。まず 2.1.248 以降への更新が前提です。

2. CLAUDE_CODE_SUBAGENT_MODEL の棚卸し(v2.1.251 の破壊的変更)
理由: 「全上書き」から「既定値」への意味変更は、エージェント定義に model: を書いている自動化の実行モデルを黙って変えます。既存の knowledge に対応項目がなく、コスト・品質の両面に効くため、今日中に該当箇所を洗い出す価値があります。
