前提: 収集元は ChatGPT(codex)と Claude の2系統だけです。両方が一致した項目と、片方だけの項目でも一次情報で確認できたものを [確認済] にしています。一次情報は、Claude Code の changelog、platform.claude.com、anthropic.com、claude.com/blog、support.claude.com、Cowork の changelog を直接取得して照合しました。

A. モデル(Opus 5.5)

A-1. Claude Opus 5.5 リリース(09-22)

  • [確認済] 両系統が一致し、一次情報とも整合しています。
  • ID は claude-opus-5-5。コンテキストは 1M、最大出力は 128k、価格は $4/$20 です。
  • キャッシュ読み取りは $0.20、Batch は半額です。公式の説明は「ほとんどの作業で Fable 5.1 と同等、コストは Opus 5 より 40% 安い」です。
  • 出典: https://www.anthropic.com/claude-opus-5-5 / https://platform.claude.com/docs/en/release-notes/overview / https://support.claude.com/en/articles/12138966-release-notes

A-2. Opus 5.5 のベンチマークと Fast mode

  • [確認済] Claude だけが挙げた項目ですが、公式ページに同じ数値がありました。
  • ベンチマーク: Terminal-Bench 4.0 が 66.4%、CursorBench 4.0 が 57.8%、OSWorld 2.0 が 81.8%。
  • Fast mode は Claude API 限定の research preview で、$8/$40、速度は最大 2.5 倍です。
  • 公式ページ自身が「ベンチマークの差は実務での差の指標として当てにならなくなってきた」と注記しています。
  • 出典: https://www.anthropic.com/claude-opus-5-5

A-3. Opus 5.5 の破壊的変更と挙動の違い

  • [確認済] 両系統が一致し、一次情報とも整合しています。
  • 次の指定は 400 エラーになります:
  • thinking: disabled
  • budget_tokens の指定
  • tool_choice の any / tool
  • Claude API と Google Cloud での computer_20251124(Bedrock では引き続き使えます)
  • effort を省略したときの既定値は medium です(Opus 5 では high)。同じ effort でも思考量は多めになります。
  • ツール呼び出しの間に書かれるテキストは thinking ブロックとして返り、既定の表示設定では空になります。
  • 一次情報には、両系統が触れていない注意点もあります。
  • 2026-08-31 以降に作られたアカウントでは、前の部分が変わった thinking ブロックを送り返すと既定で 400 になります(prefix binding)。
  • 公式は、会話を追記のみにして、指示の変更は mid-conversation system message で入れるよう推奨しています。
  • 出典: https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5

B. Claude Code(最重要)

B-1. v2.1.280(09-22)

  • [確認済] 両系統が一致し、changelog 原文と整合しています。
  • Opus 5.5 を追加し、Opus の既定モデルにしました。
  • CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH を追加しました。
  • hook_execution_complete の OTel イベントに、hook 出力のサイズを追加しました。
  • 再開したフォーク型サブエージェントがツール一覧を作り直して prompt cache を壊す不具合を修正しました。
  • ホストアプリ(Desktop / VS Code / SDK)からモデルを切り替えたときに cache miss が起きる不具合を修正しました。
  • auto mode で、安全チェックに断られた操作を何度も再試行する不具合を修正しました。
  • 出典: https://code.claude.com/docs/en/changelog

B-6. v2.1.275 の変更

  • [確認済] Claude だけが挙げた項目ですが、changelog 原文で確認できました。
  • 実行中のターンを中断してすぐ送る send-now キー(ctrl+enter / ctrl+x ctrl+s)を追加しました。
  • claude.ai で有効にしている skills / plugins がターミナルに同期されるようになりました。止めるには syncClaudeAiSkills: false / syncClaudeAiPlugins: false を設定します。
  • __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__ 行を使ったときのキャッシュ効率が改善しました。

B-8. v2.1.273 の変更

  • [確認済] blockReadsOutsideWorkingDirectories を設定すると memory ディレクトリも読み込まれなくなる修正です。
  • [確認済] v2.1.268 の deny ルールの変更を差し戻しました。
  • 対象は、権限チェッカーが解析できない Bash 行(eval、env -C)に Read/Edit の deny ルールを当てる変更です。
  • time -p make build のようなコマンドは、deny されずに再び確認を求めるようになります。
  • 取得のたびに要約の版数が揺れました(1回目は 2.1.269、原文引用付きの2回目は 2.1.273)。原文を引用した方を採用しています。
  • [棄却:版数] auto mode で skill 内の ! シェルコマンドが通常の権限ルールに従う件は、Claude の言う 2.1.273 ではなく 2.1.271 です。

B-9. v2.1.274:hooks で動かすセッション(/goal など)が「Prompt is too long」で止まる不具合の修正、起動の高速化

  • [要検証] Claude だけが挙げた項目です。今回の取得では 2.1.274 に該当する行を確認できませんでした。
  • 似た修正が 2.1.269 にあることは確認しました。2.1.274 に該当行がないと確認したわけではありません。

今日の注目

  1. Opus 5.5 への移行前に、自分のスクリプトを点検する
  • Claude Code 2.1.280 から、Opus の既定モデルは Opus 5.5 です。
  • API を直接呼ぶ部分で、次の指定が残っていると 400 エラーになります:
  • thinking: disabled
  • budget_tokens
  • tool_choice: any/tool
  • effort を省略していると、high から medium に下がって品質が変わる可能性があります。
  • 対処として、claude-opus-5-5 を指定している箇所を grep で洗い出し、effort を明示してください。
  1. 2.1.280 のキャッシュ修正を E-1 の /usage で測る
  • 修正のうち2件は、前回知見の prompt cache 前提(フォーク型サブエージェント、モデル切り替え)に直接関わります。
  • 公式が示す手順(/usage と prompt-audit)で、アップデート前後の cache share を比較する価値があります。
  • Opus 5.5 から Fable 5.1 への切り替えでは、API 上は推論内容が引き継がれることも一次情報で確認しています。
  1. syncClaudeAiSkills / syncClaudeAiPlugins(2.1.275)の影響を確認する
  • claude.ai 側で有効にしている skills / plugins がターミナルにも同期されるようになりました。
  • これにより、headless の cron 実行で読み込まれるスキルが増え、実行結果の再現性やスキル一覧のコンテキスト予算に影響するおそれがあります。
  • 自動化の環境で false にすべきか、実際に試して判断してください。
