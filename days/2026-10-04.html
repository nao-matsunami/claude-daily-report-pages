Sonnet 5 → 5.5 の破壊的変更5点

[確認済] 収集では Qiita(二次情報)が出典でしたが、Platform release notes(09-28)に同じ5点が載っていました。

  1. thinking 無効は disabled ではなく {"type":"between_tools"} で指定する。effort が high 以下のときだけ有効
  2. tool_choice の any / tool は400エラーになる
  3. thinking ブロックは生成したアカウント(と紐付いたアカウント)でしか使えない。他のアカウントから送ると黙って捨てられる
  4. Claude API と Google Cloud では computer_20251124 を受け付けない
  5. advisor ツールは Opus 4.8 / Opus 4.7 / Sonnet 5 を advisor として受け付けない

3 は Qiita の「使い回せない可能性」より具体的です。

出典: https://platform.claude.com/docs/en/release-notes/overview

2. Claude Code(重点)

v2.1.284(09-28): Sonnet 5.5 を既定に / 権限モード未設定なら auto mode で起動

[確認済] changelog 原文で次を確認しました。

  • Sonnet 5.5(1M コンテキスト)が既定の Sonnet になった
  • 権限モードを設定していない場合は auto mode で起動する
  • /effort ultracode [on|off] が独立したトグルになった(xhigh を強制しなくなった)
  • /rate-limit-options と /mcp reconnect all が追加された
  • compact 後も「Prompt is too long」が続く問題が直り、再 compact するようになった

収集内容の訂正: auto mode 既定の対象を、収集は「ターミナルと VS Code」としていました。原文は「interactive terminal, desktop app, VS Code」です。

v2.1.285(09-29)

[確認済] changelog 原文で次を確認しました。

  • claude --desktop、claude plugin configure、CLAUDE_CODE_DISABLE_WEB_FETCH、managed setting の allowedProviders が追加された
  • fork サブエージェントが plan mode / dontAsk を引き継ぐようになった
  • 同期 hook がバックグラウンドプロセスの出力待ちで止まる不具合が直った

収集内容の訂正(2点):

  • バックグラウンド Bash/PowerShell のタイムアウト(既定30分、最大2時間)は、原文では 「unattended sessions only」、つまり無人セッション限定です。収集ではこの限定が抜けていました。
  • _meta['anthropic/alwaysLoad'] の変更は、原文では 2.1.283 です。収集の 2.1.285 は誤りです。

v2.1.286(09-30)

[確認済] changelog 原文で次を確認しました。

  • 前のセッションが落ちた場合に、--resume / --continue で並列ツール呼び出し後のターンが失われる不具合が直った
  • バックグラウンドエージェントを表示中に打った /compact /clear /rewind がメイン会話に作用する不具合が直った。今は対象を示した確認ダイアログが出る
  • verify という名前の skill があれば、コミット直前に実行するよう指示されるようになった。docs のみ・tests のみのコミットは除外

v2.1.287(10-01): Claude Mods

[確認済] changelog 原文で次を確認しました。

  • 「plugins may now modify deeper behavior」とする Claude Mods が追加された
  • 組み込み mod「You should know」が追加された。/plugin enable cc-plugin-you-should-know@builtin で有効化し、「first-party sessions with telemetry on」の場合に限られる(この条件は収集にありませんでした)
  • フォルダの CLAUDE.md が二重に読み込まれる不具合が直った

収集にある「JS/TS ハンドラ」「Claude のターンを消費しない /command」などの機能の中身は、changelog の要約からは読み取れていません。

出典: https://code.claude.com/docs/en/changelog

[要検証] changelog からは、組み込み mod が opt-in であることしか読み取れません。サードパーティ mod が既定で動くのか、サンドボックスがあるのかは一次情報で確認できていません。「誤り」とも判断していません。

v2.1.288(10-02)

[確認済] changelog 原文で次を確認しました。

  • PreToolUse / PermissionRequest hook は、マッチに失敗したり JSON 化できなかったりした場合に、スキップされずにブロックされるようになった
  • bypassPermissions モードや shell allow ルールの下で、bash -c / sh -c 内の危険な rm が安全装置を失う不具合が直った
  • API が途中でタイムアウトしても、非対話セッションとサブエージェントは途中の応答から続行するようになった
  • 「Prompt is too long」が出る不具合(直前の応答のトークン使用量が0と報告された場合)が直った
  • --resume で compaction が復元した内容が落ちる不具合が直った
  • idle_prompt hook が誤って発火する不具合が直った
  • /code-review --max-findings が追加された

今日の注目

  1. v2.1.288 の hook fail-closed 化(PreToolUse / PermissionRequest)
  • 自作 hook のマッチ条件や JSON 出力にバグがあると、これまでは素通りでしたが、今後はツール呼び出しが止まります。
  • headless の定期実行では、黙って止まる形で効いてきます。
  • 既存の hooks を棚卸しして、2.1.288 で実際に動かしてみる価値が最も高い項目です。
  1. Sonnet 5.5 の破壊的変更と、2.1.284 で既定 Sonnet になった件
  • Sonnet をエイリアスで指定しているスクリプトは、自動的に Sonnet 5.5 に切り替わります。
  • そのため、thinking: disabled、tool_choice: any/tool、computer_20251124 を使っているコードは 400 エラーになるおそれがあります。
  • Opus 5.5 のときと同じ形で、Sonnet 5.5 版の棚卸しをするとよいです。Sonnet 4.5 の廃止日(11-30)の固定 ID 検索も一緒にできます。
  1. Cowork のクラウド移行(10-06、2日後)
  • 「Only on your computer」が削除され、定期タスクがクラウドに移ります。
  • ローカルファイルを使う定期タスクは、デスクトップアプリを開いておかないと動きません。
  • 発効前に、自分の定期タスクがどう動くか確認しておく価値があります。
