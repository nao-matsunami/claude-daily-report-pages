  • [棄却（理由部分のみ）] Gemini の「トークン消費とレイテンシ削減のためデフォルト無効化」という動機の説明は changelog に存在しない。無効化の事実は正しいが、理由は Gemini の補完。

v2.1.233 の Windows auto mode リグレッション修正 ＋ 2.1.232 の Bash 権限変更の一部差し戻し

[確認済] 3AIとも触れていないが原文にあり、実運用に効くので拾う。cd <dir> && <command> > file で auto mode が毎回止まる 2.1.232 リグレッションを修正し、Cygwin 風シンボリックリンクと入力リダイレクト（< file）の権限変更はいったん差し戻し（後日狭い形で再導入予定）。

[確認済] サブエージェント fork の既定 ON（会話全体とプロンプトキャッシュを継承、対話セッションでの非 teammate エージェント起動は既定でバックグラウンド）、sandbox.ripgrep のプロジェクト設定禁止、ネスト git リポジトリの trust 継承修正、PowerShell $PSDefaultParameterValues 経由の権限バイパス修正、/code-review の high/xhigh/max もバックグラウンド化、「カスタムサブエージェントを作りましょう」起動 Tip と /powerup ツアー誘導の削除 — すべて原文で一致。

今日の注目

  1. v2.1.233 の Todo/タスクツール停止（CLAUDE_CODE_ENABLE_TODO_TOOLS=1）

Opus 4.8 / Sonnet 5 / Fable 5 / Mythos 5 以降で TodoWrite・TaskCreate 系が消えるのは、既存のフック・スキル・自動化が黙って壊れるタイプの変更。この repo の verify パイプラインや cron スクリプトが TodoWrite 前提のマッチャを持っていないか、grep 一発で棚卸しする価値がある。fork 既定 ON のときと同種の影響範囲監査がそのまま流用できる。

  1. v2.1.233 の「2.1.232 Bash 権限変更の差し戻し」＋ Windows auto mode リグレッション修正

< file 入力リダイレクトと Cygwin 風シンボリックリンクの権限チェックが一度入って戻された＝「後日狭い形で再導入」と明言されている。つまり今の挙動は暫定。この間に deny ルールやフックを 2.1.232 の挙動前提で組むと、再導入時にもう一度壊れる。今週のうちに「どちらの挙動でも成立する書き方」に寄せておくのが安い。

  1. 週次上限 +50% の 8/19 終了

検証パイプラインを回す前提のスループットが来週から素で 1/1.5 になる。今日〜8/19 の間に重い一次検証（自己ホストランナー公式ブログ、arXiv 2608.07776、CVE-2026-54316 の影響バージョン範囲）をまとめて消化し、8/20 以降は軽い差分確認に切り替える、という計画変更が実利として一番大きい。

補足（確認の不在について）: 今日「一次で確認できなかった」ものは、auto mode の 89%/14% 検出率、Desktop の自動再開チェックボックス、Cowork の Gmail/Drive 書き込み自律実行拡大、Chat/Cowork ホームタブ統合、Slack 分析記事、arXiv 論文、CVE の影響バージョン範囲です。これらは「存在しない」とは書いていません。一方で「存在しない／誤りである」と断定できるのは、v2.1.230（欠番）、Gemini の v2.1.228 記述2件、@session_id 形式、透かしの「適用済み」時制、Claude Design の今週の公式発表（なし）の各点です。
